# 邀请码身份与准入

> 本文是面向用户与贡献者的导读，完整设计见 [02-5 邀请码身份与准入体系](https://gitee.com/perry-space/study-club/blob/master/docs/02-系统架构/05-邀请码身份与准入体系.md)（Gitee）。

**一句话结论**：邀请码 + 自设密码是**不需要手机号 / 微信 / 企业主体**的身份方案。

## 一、为什么用邀请码

| 问题 | 没有身份时的困境 | 邀请码方案的解法 |
| --- | --- | --- |
| **跨设备 / 换设备** | 服务端数据无法归属到某个家庭 | 邀请码即身份 → 同一码 + 密码可在任意设备访问同一档案空间 |
| **增长不可控** | 完全开放 → 反馈噪音大 | 邀请制 → 小规模内测、渐进放量 |
| **账号需要企业主体** | 手机号短信需企业实名；微信登录需企业认证 | ⭐ 邀请码既不发短信、也不接微信 → **不需要企业主体** |

| 原「标准账号」需要 | 邀请码方案 |
| --- | --- |
| 短信服务（企业实名 + 费用） | ❌ 不需要 |
| 微信开放平台（企业认证） | ❌ 不需要 |
| 实名认证 | ❌ 不需要 |

## 二、先分清两个概念

| 概念 | 回答的问题 | 可否独立开关 |
| --- | --- | --- |
| **准入（Access）** | 「你有没有资格进来？」 | ✅ 可开关（邀请制 / 免码开放） |
| **身份（Identity）** | 「你的档案是哪个？」 | ✅ 可开关（`enableInviteAuth`） |

> 这一区分让「邀请制」与「免费开放给所有用户」并不冲突：开放的是**准入策略**，身份模型与是否收费无关。

## 三、邀请码的三种角色

| 角色 | 说明 | 是否必需 |
| --- | --- | --- |
| **准入凭证** | 有码才能注册，控制放量节奏与质量 | 可关闭 |
| **身份凭证** | 码 + 密码 = 一个家庭档案空间的唯一标识 | ✅ 核心 |
| **家庭凭证** | 同一码供家庭成员共用，对应「一个家庭 = 一个档案空间」 | ✅ 核心 |

> ⭐ **「一码一账号」**：邀请码承担**身份凭证**角色，登入时用「码 + 密码」定位到唯一账号，
> 因此一个码只可能激活一个账号。**家庭共享 = 全家人用同一个码 + 同一个密码进同一个档案空间**，
> 而不是各自注册。

## 四、注册与登入

**注册**：

```
① 输入邀请码（require_invite 开启时必填）→ 服务端校验（限流）
② 设置账号标识与密码（用户名 / 密码至少填一；密码 ≥ 6 位）→ 密码二次确认
③ 设置家庭昵称（可跳过，默认「我的家」）
④ 创建首个孩子档案（昵称 + 年级，不收真实姓名）
⑤ ⭐ 显示「恢复码」，要求抄下并确认（仅显示一次）
⑥ 完成 → 服务端创建账号与档案并签发会话
```

**登入**：输入账号标识（邀请码或用户名）+ 密码 → 服务端校验 → 签发 JWT Access（短期）+ 可吊销 Refresh。

> **存储口径**：学习记录、儿童档案、进度与复习状态全部存服务端 MongoDB，前端不持有业务数据。

## 五、⚠️ 找回机制（必须诚实设计）

**没有手机号，就无法用「验证码找回」**。这是邀请码方案的固有代价：

| 情况 | 可用手段 |
| --- | --- |
| 忘记密码，但记得恢复码 | ✅ 恢复码重置密码 |
| 忘记密码与恢复码 | ❌ 云端档案无法找回（此前导出的备份文件可重新导入） |
| 换设备，记得码与密码 | ✅ 直接登入 |

> ⚠️ UI 必须明确告知：**忘记密码且丢失恢复码将无法找回云端备份，请妥善保存恢复码**。

## 六、安全设计

| 威胁 | 对策 |
| --- | --- |
| 码被枚举 / 爆破 | 码 ≥ 60 bit 熵 + 服务端限流 + 失败锁定 |
| 码在群里被转发 | `max_uses` 限制 + 用量可观测 + 可吊销 |
| 码泄漏但密码未知 | 无法登入（密码是第二因素） |
| 密码弱 | 服务端限流 + Argon2id 加盐哈希 + 强度下限 |
| 服务端读到儿童数据 | ⭐ 端到端加密同步 |

**码的生成**：Crockford Base32（去掉易混的 `I`/`O`/`U`/`L`），**12 位**（分 3 组 `XXXX-XXXX-XXXX`，60 bit 熵），服务端 `secrets` 随机生成，**只存哈希**。

**双因素：码 + 密码**

| 因素 | 承担 | 强度 |
| --- | --- | --- |
| 邀请码 | 准入（是否被允许） | 高熵，但可能被共享 / 泄漏 |
| 自设密码 | 身份确认（是否是你） | 低熵，但只有本人知道 |

> 两者缺一不可：只有码 → 群里转发也进不去（没密码）；只有密码 → 无法定位账号；码 + 密码 → 即使码被转发，他人也不知道密码。

## 七、⭐ 端到端加密同步

```
用户密码 ──► KDF（Argon2id + 盐）──► 派生密钥 ──► 客户端加密学习数据
                                                     │
                          服务端只存密文（无法解密）◄──┘
                                                     │
                          另一设备登入 → 下载密文 → 本地用同一密码解密
```

| 收益 | 说明 |
| --- | --- |
| 服务端**读不到儿童学习数据** | 合规负担大幅降低；即使服务器被入侵也不泄漏内容 |
| 密码既是认证因素也是解密密钥 | 无需额外密钥管理 |
| 信任成本低 | 开源项目最怕「你收集我孩子的数据」，此设计可直接回应 |

| 代价 | 应对 |
| --- | --- |
| 忘记密码 = 云端密文永久不可恢复 | 强制恢复码流程 + 导出兜底 + UI 明确警告 |
| 服务端无法分析学习内容 | 统计只做**聚合计数** |

> **默认开启端到端加密**（`enableE2EEncryption` 默认开）。**先严后宽，而不是先宽后严。**

## 八、准入策略

准入由运行期开关 `require_invite`（环境变量 `REQUIRE_INVITE`）与构建期开关 `enableInviteRequired` 共同决定。

| 策略 | `REQUIRE_INVITE` | 说明 |
| --- | --- | --- |
| 邀请制内测 | `true` | 维护者手工发放邀请码 |
| 免码开放 | `false` | 不校验邀请码，直接注册（**默认**） |

> **边界**：邀请码只用于控制**放量节奏**，不做收费门槛、不长期关闭公开入口、不用码绑定真实身份。
> 进入放量期后切到「免码开放」，与「免费开放给所有用户」的承诺一致。

## 九、合规影响

| 项 | 是否需要 |
| --- | --- |
| 短信服务 | ❌ 不需要 |
| 微信开放平台 | ❌ 不需要 |
| 支付商户号 | ❌ 不需要 |
| 用户实名 | ❌ 不需要 |
| 应用商店开发者账号 | ❌ 不需要 |

> ⚠️ 启用云端家庭档案后，儿童学习数据存于服务端。要求：① **默认关闭云档案**，用户显式开启；
> ② 开启时用通俗语言告知上传内容、加密方式与删除方法；③ **默认端到端加密**，使服务端不可读。
