# 存储与后端策略

> 本文是面向用户与贡献者的导读，完整设计见 [02-3 存储与后端策略](https://gitee.com/perry-space/study-club/blob/master/docs/02-系统架构/03-存储与后端策略.md)（Gitee）。

结论：**服务端为唯一真源 + 内容即仓库 + 单机自托管后端**。学习数据、儿童档案、进度与内容全部存服务端
MongoDB；浏览器只保留凭据与少量 UI 偏好；内容以仓库内 JSON 维护、导入数据库后经接口下发。

## 一、为什么以服务端为准

| 动机 | 说明 |
| --- | --- |
| **跨设备一致** | 同一账号在手机 / iPad / 桌面看到同一份进度 |
| **多档案与家庭共用** | 儿童档案、多孩切换、家长查看天然由服务端承载 |
| **学情报告可信** | 报告在服务端基于全量记录聚合，口径统一、可复算 |
| **内容集中管理** | 内容改一处即对全体用户生效，不必等客户端发版 |
| **复习调度可演进** | 调度计算放在服务端，避免各端算法漂移 |

## 二、存储分层

| 层 | 载体 | 存什么 |
| --- | --- | --- |
| 业务数据 | **MongoDB** | 账号、设备、儿童档案、学习记录、答题记录、复习状态、错题、每日任务、徽章、同步对象 |
| 内容数据 | **MongoDB** | 字库、古诗、单元、关卡、故事、短文、徽章定义、内容清单 |
| 素材文件 | **磁盘 / 命名卷 + `assets` 集合** | 图片、音频、笔顺 JSON（内容文档只存 `*_ref`，出参展开为 `*_url`） |
| 匿名统计 | **MongoDB** | 功能使用计数、完成度、错误分布（聚合，无个人标识） |
| 浏览器 | **localStorage（仅四类键）** | 会话凭据、设备标识、UI 偏好、登录记忆 |

## 三、浏览器只保留四类键

前端**不持有业务数据**，localStorage 只允许承载四类键：

| 键 | 用途 | 为什么留在本地 |
| --- | --- | --- |
| `sc.session` | 会话凭据（JWT） | 路由守卫首个 tick 就要判断登录态，必须**同步可读** |
| `sc.deviceId` | 设备标识 | 服务端按 `client_id` 建 `devices` 记录，区分同账号多设备会话 |
| `sc.currentChild` | 当前选中的孩子 | 纯 UI 偏好，丢了重选即可 |
| `sc.loginMemory` | 记住的账号与密码 | 用户显式勾选才写，仅本机、不上传 |

> ⚠️ **纪律**：数据访问一律走 `packages/core` 的仓储与 API 客户端，组件内不得直接读写存储。

## 四、内容即仓库

内容与代码**物理分离**：内容以仓库内 JSON 维护，贡献者**只需改 JSON**，不必懂前端。

```
content/
├── manifest.json          # 内容包清单：版本、各文件哈希、条目数
├── characters/grade-1.json
├── poems/required-75.json
├── lessons/units.json     lessons/lessons.json
├── stories/stories.json   badges/badges.json
├── schema/*.schema.json   # JSON Schema（CI 校验 + 后台表单共用）
└── sources.json           # 数据来源与许可清单
```

| 环节 | 实现 |
| --- | --- |
| 维护 | Git（仓库内 JSON）：版本、评审、回滚、审计由 Git 天然承担 |
| 校验 | JSON Schema + `scripts/content/validate.mjs` |
| 导入 | `scripts/seed`（按表拆分）或后台导入，upsert 幂等 |
| 下发 | `GET /content/bootstrap` 一次拉全量 + 子资源接口按需读取 |

**内容版本**：`content_version` + `min_app_version` + `checksum` + `counts`。
客户端忽略要求更高版本的内容，避免「字段不认识 → 渲染崩溃」。

## 五、后端职责

| 类型 | 能力 | 处理 |
| --- | --- | --- |
| **可以做**（只需服务器） | 内容读取、邀请码校验与身份、匿名统计、云端家庭档案与加密同步、反馈、素材托管、单管理员内容后台 | ✅ 已实现并部署 |
| **必须掩藏**（需企业主体） | 手机号 / 微信账号、支付与订阅、推送、微信小程序、iOS / Android App | ⛔ 写契约与开关，不注册路由、不打包、不可达 |
| **本期不做**（设计取舍，**不需要企业主体**） | 多角色 RBAC 后台 | ⛔ 单管理员足够，多角色属过度设计 |
| **交给本地**（无业务数据） | 会话凭据、设备标识、UI 偏好 | ⭐ 浏览器 localStorage 四类键 |

> **关键区分**：**「不做需要企业主体的事」不等于「不能有服务器」**。邀请码身份、内容后台、匿名统计、跨设备同步**只需服务器**，属于已实现范围；**多角色 RBAC 也与企业主体无关**，它是「单人维护下不做」的范围决定。

## 六、鉴权与会话

| 项 | 设计 |
| --- | --- |
| 学习者身份 | 邀请码 + 自设密码（用户名 / 密码至少填一） |
| 密码存储 | Argon2id（含盐），明文不落日志、不入库 |
| 邀请码 / 恢复码 / Refresh | 只存 SHA-256 哈希；失败信息统一以防枚举 |
| 会话 | 短期 Access（JWT）+ 可吊销 Refresh（只存哈希），按 `client_id` 区分设备 |
| 防暴力 | 失败 5 次锁定 15 分钟；按 `client_id` + IP 限流 |
| 管理员 | 密码换管理员 JWT，或 `X-Admin-Password` 头；**服务端二次校验** |

## 七、掩藏层：写代码但不启用

| 能力 | 开关名 | 默认 |
| --- | --- | --- |
| 手机号 / 微信账号 | `enableAccountAuth` | 关 ⛔ |
| 支付与订阅 | `enablePayment` | 关 ⛔ |
| 微信小程序 | `enableMiniprogram` | 关 ⛔ |
| iOS / Android App | `enableNativeApp` | 关 ⛔ |

**掩藏的准确含义**：四道防线同时成立 —— ① 路由不注册；② 组件不渲染；③ 调用即抛 `FeatureDisabledError`；④ 类型与契约**始终保留**。

> 一句话：**掩藏 = 不可打包 + 不可达 + 不可调，而不是看不见。**

## 八、备份与导出

| 层次 | 机制 | 依赖 |
| --- | --- | --- |
| **① 导出 / 导入文件** | 导出 `.json`（含 `schema_version`），可导入还原 | ❌ 无 |
| **② 恢复码** | 注册时一次性返回，忘记密码时重置 | 服务端 |
| **③ 云端家庭档案** | 家庭档案 + 端到端加密：服务端只存密文 | 服务端 |

> **核心原则**：数据主存于服务端，**导出 / 导入是备份手段，不是唯一通路**；端到端加密的云档案默认关闭、密钥由用户密码在客户端派生，**服务端没有解密密钥**。

## 九、匿名统计与隐私边界

统计的目的是「知道哪里卡住了」，不是「知道谁在用」。

| 允许 | 禁止 |
| --- | --- |
| 功能使用次数、内容完成度（聚合） | 任何个人身份信息（姓名、手机号、微信 ID） |
| 错题分布（按内容维度） | 儿童真实姓名、照片、精确位置 |
| 错误堆栈、设备类型与浏览器版本 | 录音原始数据、可识别个体的行为轨迹 |

> `stats_events` 集合**禁止** `account_id` / `child_id` / `client_id` 字段。

## 十、部署与配置

| 项 | 设计 |
| --- | --- |
| 编排 | `deploy/` 下四份**独立** compose：`mongo` / `api` / `web` / `admin` |
| 网络 | 均 `network_mode: host`，不做端口映射 |
| 前端托管 | nginx 托管构建产物 + `/api/` 同源反代到 `127.0.0.1:8000` |
| 配置 | 密钥只走环境变量（见根 `.env.example`） |
| 备份 | 每日 dump（内容 + 身份 + 统计），见 `scripts/db/backup.sh` |

> ⚠️ **含 `$` 的环境变量值（Argon2 哈希、base64 密钥）必须用单引号包住**：Docker Compose 用 dotenv 解析，未加引号会把 `$xxx` 替换成空串。
