# 多端适配

> 本文是面向用户与贡献者的导读，完整设计见 [02-2 多端适配与响应式设计规范](https://gitee.com/perry-space/study-club/blob/master/docs/02-系统架构/02-多端适配与响应式设计规范.md)（Gitee）。

**当前交付**：手机 / iPad / 桌面浏览器三档响应式（Web + PWA）。
**预留形态**：微信小程序、iOS / Android App —— 属**掩藏能力**，开关默认关闭、不注册路由、不打包、不可达。

## 一、两条硬结论

1. **手机 / iPad / 桌面三端共用一套 Web 代码，靠响应式区分。** 三端差异只是「屏幕宽度 + 指针类型」，没必要拆三份代码。iPad 不是独立的端，而是断点更大、多了手写笔、多了横屏的手机。
2. **业务逻辑只写一遍，永不写在视图层。** 内核 `packages/core` 零平台依赖，视图层只做渲染。

## 二、断点定义

断点按**真实设备视口宽度**划三档，不按设备名：

| 档位 | 视口宽度 | 布局形态 |
| --- | --- | --- |
| **手机** | `< 768px` | 单列 |
| **iPad / 平板** | `768–1279px` | **双列**（窄边栏） |
| **桌面** | `≥ 1280px` | **三列**（完整侧边栏） |

实现方式：CSS 媒体查询 + `matchMedia` 的 `useBreakpoint()`。

```css
@media (min-width: 768px)  { /* iPad */ }
@media (min-width: 1280px) { /* 桌面 */ }
```

> ⚠️ 断点数值只允许存在两份（CSS 变量 + TS 常量），且必须同步修改；**不允许在组件里写魔法数字**。

## 三、三档布局形态

| | 手机 | iPad / 平板 | 桌面 |
| --- | --- | --- | --- |
| 导航 | 底部 Tab Bar（4–5 项） | 左侧窄边栏 | 左侧完整侧边栏 |
| 学习地图 | 纵向卷轴，一期 3–4 关 | 横向双列网格，一期 8–12 关 | 三列 + 关卡详情侧栏 |
| 字卡学习 | 满屏单字 | 左侧字卡 + 右侧释义 / 组词 / 笔顺并排 | 同 iPad + 第三个辅助面板 |
| 答题 | 选项纵向堆叠，矮屏切 2×2 | 选项 2×2 网格 | 题目居中，选项横排 |
| 学情报告 | 卡片纵向滚动 | 图表 2 列并排 | 图表 + 明细表并排 |

## 四、触摸、指针与热区

| 项 | 规则 | 理由 |
| --- | --- | --- |
| 最小可点击热区 | **56×56px**（主操作 ≥ 64px） | 儿童手指定位精度低于成人 |
| 相邻可点击元素间距 | ≥ 12px | 防误触 |
| `hover` 效果 | 必须包在 `@media (hover: hover)` 内 | 触屏 `:hover` 会「粘住」上一次点击态 |
| 触摸反馈 | `:active` + 缩放 / 变色，≤ 100ms | 无 hover 时即时反馈是唯一确认手段 |
| 手势 | 滑动切字卡、下拉刷新等，但**每个手势都要有等价按钮** | 认知能力与发现性 |
| 文本选中 | 全应用默认 `user-select: none`，仅 `.selectable` 与输入控件开回来 | 防长按弹菜单打断学习 |
| 缩放 | **整体关闭**（viewport + `touch-action` + Safari `gesturestart`） | 防误放大后退不回来 |

> ⚠️ 光配 viewport 不够：iOS Safari 10+ 起直接忽略 `user-scalable=no`，需叠加 CSS 与事件守卫。

## 五、安全区与视口

| 问题 | 正确做法 |
| --- | --- |
| 底部导航被 Home 指示条遮挡 | `padding-bottom: env(safe-area-inset-bottom)` |
| 刘海 / 灵动岛遮挡顶部标题 | `padding-top: env(safe-area-inset-top)` |
| 移动端地址栏导致 `100vh` 溢出 | 用 **`100dvh`**（动态视口高度） |
| 键盘弹出遮挡输入框 | `VisualViewport` API 监听 |

> ⚠️ **全项目统一用 `100dvh`**，并在 `@supports` 中为老浏览器降级为 `100vh`。

## 六、字号与流体缩放

| 元素 | 手机 | iPad | 桌面 |
| --- | --- | --- | --- |
| 正文 | 18px | 20px | 18px |
| 字卡主字 | 120–160px | 200–280px | 160–200px |
| 辅助文字（拼音 / 释义） | ≥ 16px | ≥ 18px | ≥ 16px |

```css
:root {
  --font-body: clamp(18px, 1.1vw + 14.5px, 22px);
  --font-card-glyph: clamp(120px, 26vw, 240px);
  --content-max: 880px;   /* 内容最大宽度 */
  --tap-min: 56px;
  --tap-primary: 64px;
}
```

> **大屏约束**：内容区最大宽度 880px 居中；超出宽度用于**增加信息密度（多栏）**，而不是拉大单个元素。

## 七、学习页：全部操作控制在一屏内（硬性规则）

识字闯关 / 古诗 / 故事这三条**学习中**的页面，当前这一步的全部操作必须在一个屏幕内可达 ——
页面本身不滚动，主操作按钮永远可见。

> **为什么**：6 岁孩子不会主动尝试滚动，**看不见的按钮等于不存在的按钮**。

| 区域 | 类名 | 职责 | 是否滚动 |
| --- | --- | --- | --- |
| 整页 | `.learn-page` | 视口内的一列 | ❌ |
| 顶部 | `.learn-page__head` | 进度 / 步骤 / 标题 | ❌ 常驻 |
| 内容 | `.learn-page__body` | 本步核心内容 | ✅ **唯一**滚动区 |
| 底部 | `.learn-page__foot` | 本步主操作 | ❌ 常驻 |

**矮屏分档**（横屏手机 / 小屏手机 / 小笔记本）：

| 阈值 | 处理 |
| --- | --- |
| `max-height: 820px` | 字卡主字收一档 |
| `max-height: 760px` | 页内间距收一档；4 个选项由纵向堆叠切成 2×2 |
| `max-height: 700px` | 字卡主字再收一档；聚焦大字 / 跟读题大字收档 |

## 八、iPad 专项

iPad 是**最佳学习体验端**：大屏 + 手写笔 + 家庭共用。

| 能力 | 技术 |
| --- | --- |
| 手写笔迹采集 | Pointer Events（`pointerdown/move/up` + `getCoalescedEvents()`） |
| 压感与倾斜 | `event.pressure` / `event.tiltX` / `event.tiltY` |
| 手掌防误触 | `touch-action: none` + 只处理 `pointerType === 'pen'` |
| 判分 | 笔顺序列比对 + 轨迹相似度（**不做字迹美观打分**） |

> ⚠️ 检测到手写笔时才开启手写练习入口，否则默认走「描红跟写」的宽容模式。

## 九、能力探测与降级

统一在启动时探测一次，产出能力对象注入到 core，**不要用散落的 `if (isXXX)`**。

| 能力缺失 | 降级行为 |
| --- | --- |
| 无法实时音频分析 | 改为「录 2 秒 → 停止 → 分析 → 出结果」 |
| 无手写压感 | 走「描红跟写」的宽容模式 |
| 无 PWA 安装 | 隐藏「添加到主屏幕」引导 |
| iOS 无推送 | 引导开启 Web App 通知 |

> ⚠️ **降级不等于隐藏**：能降级实现的功能要降级实现，只有当降级也无法实现时才隐藏入口。

## 十、分端性能预算

| 指标 | 手机（4G） | iPad（WiFi） | 桌面 |
| --- | --- | --- | --- |
| 首屏可交互 | < 2s | < 1.5s | < 1.5s |
| 首屏 JS（gzip） | < 150KB | < 200KB | < 200KB |
| 字卡切换 | < 100ms | < 100ms | < 100ms |
| 声调评测出结果 | < 300ms | < 300ms | < 300ms |
