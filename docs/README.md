## 一、六条前置约束（决定一切）

这六条是当前阶段的硬约束，任何方案都必须满足。**这是六条约束在全套文档中的唯一定义处**，其他文档引用而不重复：

1. **不做需要企业主体的能力** —— 不做手机号/微信账号、支付、小程序、App 上架、短信
2. **上线前全部免费开放给所有用户** —— 不向用户收费
3. **项目最终可能开源** —— 贡献者必须能零成本、零密钥地克隆运行
4. **✅ 已有服务器** —— 后端可以做，且只能做「轻」职责（内容管理、匿名统计、可选同步）
5. **✅ 可以有云端后台，可部署到服务器云端** —— 后端**不是空壳预留，是真实部署的目标形态**（形态 B）
6. **✅ 付费项优先用免费方案，少量付费可接受** —— 付费能力必须**可选、可降级、默认关闭**

**由此推出架构**：**本地优先 + 内容即仓库 + 已部署的云端后台（非必需依赖）+ 企业能力掩藏**。

```
不做企业主体的事 ──┐
                   ├──► 手机号/微信账号、支付、小程序、App → ⛔ 写代码但不启用（掩藏）
免费开放给所有用户 ─┤
                   ├──► 不收费 → 成本须极低，优先免费方案
已有服务器 ────────┤
                   ├──► ✅ 云端后台可部署：内容管理 · 匿名统计 · 邀请码校验 · 可选同步
云端后台可部署 ────┤
                   ├──► ✅ 后端真实上线（非空壳），但故障可降级、缺失不阻塞
少量付费可接受 ────┤
                   ├──► ✅ 付费服务可用，但必须可选可降级
项目可能开源 ──────┘
                       └──► 克隆后不配密钥、不付费、不部署后端也要能完整运行
```

> ⚠️ **最关键的一条区分**：**「不做企业主体的事」不等于「不能有服务器」**。
>
> | 类型 | 例子 | 处理 |
> | --- | --- | --- |
> | **要企业主体** | 手机号/微信账号、支付、小程序、App 上架 | ⛔ 掩藏 + 契约预留 |
> | **只要服务器或少量花钱** | **邀请码身份**、云端内容后台、匿名统计、跨设备同步、云端语音评测 | ✅ **可做且已部署** |
> | **都不要最好** | 本地存储、本地模型、静态内容、复习算法 | ⭐ 首选 |
>
> ⚠️ **「掩藏」的准确含义**：需要企业主体的能力**不做，但不能不做设计**——契约、类型、开关、目录骨架全部写好，代码存在但**默认关闭、不打包、不部署**。将来具备主体时是「打开开关 + 换一次注入」，而不是「重写一遍」。机制见 [02-4 第四章](./02-系统架构/04-本地优先与后端策略.md#四能力开关体系前端掩藏的实现机制)。
>
> ⚠️ **「已部署的云端后台」不等于「必需依赖」**：后端会被真实部署上线，但**前端在不连后端时仍功能完整**（学习、复习、导出全部可用）。这是开源可运行性的底线，也是服务器故障时的兜底。

## 三、当前状态一句话

**这是一个功能骨架完整、视觉完成度较高的单机原型，与「可免费开放给陌生人使用」之间还差一层本地内核与内容重建。**

- ✅ 已有：7 个孩子端功能页、完整视觉体系（2189 行 CSS）、游戏化机制、本地学习进度
- ⚠️ 半成品：字库 3500 条中**绝大多数是自动填充的占位数据**，真正精编的仅 52 条（完成度 **1.7%**）
- ❌ 内核缺失：无仓储层抽象、无能力开关、无数据导出、多档案都存不了（IndexedDB 用单 key）
- ❌ 内容缺失：全库**零古诗**（虽然训练模式里写了「古诗词填字」）
- ⛔ **必须移除**：`supportData.ts` 里的 58 个教材单元、自动填充的 3448 条字库——**来源无法溯源，开源即侵权风险**
- ⛔ **不可入库**：根目录散落的一次性脚本（含本机绝对路径且暴露数据生成方式）

详细盘点见 [01-1 原型资产与重构范围](./01-产品规划/01-原型资产与重构范围.md)。

## 四、技术栈约定

本项目**从 React 原型重构为 Vue3 正式版**，采用**本地优先 + 内容即仓库**架构，前端为**一套内核、两套外壳（当前）+ 一套预留外壳**。

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端（Web） | Vue 3 + TypeScript + Vite | 手机 / iPad / 桌面三档响应式 + PWA |
| 跨端内核 | **`packages/core`** | 算法 / stores / 类型 / 契约 / 开关，**零平台依赖 + 学科无关**，多端共用 |
| 学科包 | **`packages/subject-hanzi`** | 识字专属逻辑（不得写进 `core`） |
| 状态管理 | Pinia | 按领域拆分 store |
| **数据存储** | **IndexedDB + Cache Storage** | ⭐ **运行时主存储，无数据库依赖** |
| **身份与准入** | **邀请码 + 自设口令**（Ed25519 离线签名码 / 服务端校验） | ⭐ 不需要手机号与微信，**不需要企业主体** |
| **跨设备同步** | 可选云端家庭档案 + **端到端加密**（口令派生密钥，服务端只存密文） | 默认关闭、默认加密 |
| **内容分发** | **仓库内 JSON + 远端静态覆盖 + 可选后端接口** | ⭐ 内容即仓库，改内容不必发版 |
| **内容校验** | JSON Schema + CI 脚本 | 贡献者只改 JSON，CI 自动校验 |
| **部署** | 静态托管 + **云端后台（Docker Compose，FastAPI + MongoDB）** | ⭐ 成本≈¥0（服务器已有） |
| 许可 | 代码 MIT / 内容 CC BY-SA 4.0 / 第三方许可随分发 | 见 [01-4 第四章](./01-产品规划/04-免费开放与开源策略.md#四开源策略) |

### 部署入口与学科路由

唯一入口 **`study.example.com`**（学科无关 + 品牌无关，**改名与扩科都不作废**）；学科走 **URL 路径** `/hanzi` `/english` `/math`，不开子域。

> **理由一句话**：子域 = 不同源 → **IndexedDB 按源隔离，家长的跨科学情报告做不出来**；同时邀请码身份、PWA 安装、离线缓存都会被迫按学科各来一套。配套子域（`api.` / `admin.` / `docs.`）按需再建，一条通配符 DNS + 一张通配符证书即可覆盖。

### 掩藏层（写代码 · 开关关闭 · 不打包 · 不部署）

| 能力 | 开关名 | 状态 |
| --- | --- | --- |
| 手机号 / 微信账号 | `enableAccountAuth` | ⛔ **需企业主体**，契约保留 |
| 支付与订阅 | `enablePayment` | ⛔ **需企业主体**，集合与契约保留 |
| 微信小程序 / iOS·Android App | `enableMiniprogram` / `enableNativeApp` | ⛔ **需企业主体**，目录与分包方案保留 |
| ICP 备案 | — | ⚠️ **取决于服务器位置**：境外免备案；境内必须备案（个人主体可做非经营性备案） |

### 云端后台组件（形态 B · ✅ 部署目标）

| 组件 | 选型 | 状态 |
| --- | --- | --- |
| 后端服务 | Python 3.12 + FastAPI | ✅ **要部署**（内容管理 / 统计 / 邀请码校验 / 可选同步） |
| 数据库 | MongoDB 7 | ✅ 自托管，内容与身份/统计 |
| 缓存 | — | ❌ 不引入（内容量小，全量进内存） |
| 对象存储 | COS / OSS | ⏸️ 仅素材体积超限时才考虑 |
| 部署方式 | Docker Compose 单机 | ✅ 一键起服务，密钥只走环境变量 |
| 多角色 RBAC 内容后台 | — | ⛔ 需账号体系，当前只做**单管理员** |

> ⚠️ **两条最要紧的纪律**：
> 1. `packages/core` 中一旦出现 `window`、`document`、`uni.xxx`，跨端复用率会从 95% 掉到 0；且核心逻辑必须**与学科无关**（判据：*这段逻辑换成英语单词还成立吗？*）—— 见 [06-1 §2.9](./06-工程规范/01-开发规范与前端架构.md)
> 2. **所有数据访问必须走仓储层**，禁止组件内直接操作 IndexedDB / localStorage。这是「将来能一行不改接后端」的唯一保证（见 [02-4 5.3](./02-系统架构/04-本地优先与后端策略.md#53-适配器模式将来接后端只改一处)）

> 前端为何从 React 换成 Vue3、现有代码如何取舍，见 [06-2 React 原型迁移方案](./06-工程规范/02-React原型迁移方案.md)。

## 六、文档维护约定

1. **单一事实来源**：字段定义只在 `03-2 数据字典` 中维护，其他文档引用而非复制。
2. **契约以类型为准**：`packages/core` 中的 TS 类型是接口契约的最终事实来源，`04-1` 用于设计评审与并行开发。
3. **变更留痕**：架构或数据模型的破坏性变更通过 Git 提交信息留痕（**文档内不维护版本号与变更记录**）。
4. **命名统一**：集合名与字段名一律 `snake_case`，前端组件名用 `PascalCase`。
5. **不写空话**：文档中的每条功能描述都应能对应到一个字段、一个接口或一个页面。写不出来，说明需求还没想清楚。
6. **许可标注义务**：任何引入的第三方数据、素材、依赖，必须同步登记到 `content/sources.json` 与 `THIRD_PARTY_NOTICES.md`。**未登记来源的资产不得入库**——这是开源项目的法定义务。
7. **能力分级标注**：任何涉及后端、账号、支付、小程序、App 的内容，必须显式标注属于以下哪一类，并给出能力开关名：
   - ⛔ **掩藏**（需企业主体）：手机号/微信账号、支付、小程序、App
   - ✅ **可做且已部署**（只需服务器或少量付费）：邀请码身份、云端内容后台、匿名统计、跨设备同步、云端评测
   - ⭐ **首选**（本地即可）：本地存储、本地模型、复习算法
8. **命名与商标**：以仓库代号 `study-club` 指代本项目——**代码代号与产品名解耦**，代号不涉及商标、可自由使用，但**不得当作产品名对外**。禁止描述性名字（`汉字岛` / `识字星球` 这类）。对外正式命名前，须自行完成一遍商标与同名排查。
9. **只写能指导实现的内容**：不写方案对比与过程叙述（「原方案」「本轮新增」「已由 vX.Y 修正」之类一律不写）。结论若指导实现，改写成陈述句保留；论证过程不进文档。
