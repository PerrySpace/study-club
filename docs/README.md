# study-club · 设计文档

> 面向小学阶段的课内识字 + 古诗文启蒙应用 —— **免费开放、开源、可自托管**
>
> 代码许可 **MIT** · 内容许可 **CC BY-SA 4.0** · 联系 **perry@perryspace.club**

| 项 | 内容 |
| --- | --- |
| 产品定位 | 小学 1–6 年级课内识字 + 古诗文启蒙 |
| 目标用户 | 小学在读学生（主）、家长（陪伴与查看）、语文教师（选配） |
| **商业模式** | **免费开放**：无付费墙、无会员、无广告、无内购 |
| **身份方式** | **邀请码 + 自设密码** —— 不需要手机号、不需要微信、**不需要企业主体** |
| **当前覆盖终端** | 手机 / iPad / 桌面浏览器（Web + PWA）三档响应式 |
| **数据归属** | 学习数据存自托管服务端；可选云端家庭档案，**默认关闭且默认端到端加密** |
| **技术形态** | **服务端权威**：Vue 3 PWA 前端 + FastAPI + MongoDB 后端 + 内容即仓库 |

**完整的「是什么 / 定位 / 现状」见 [01-1 项目概述与定位](./01-产品规划/01-项目概述与定位.md)；六条前置约束的唯一定义处也在该文。**

## 二、当前状态一句话

**这是一个服务端权威、前后端俱全的可运行系统（v0.1）：前端 Vue 3 PWA + 后端 FastAPI/MongoDB + 单管理员内容后台 + 内容仓库 + 分服务编排，已能本地起全栈联调；最大的短板是内容量。**

- ✅ 已有：Web PWA 三档响应式（学习地图 / 字卡 / 闯关 / 每日任务 / 复习 / 错题本 / 古诗 / 故事 / 报告 / 设置）、邀请码身份、云端后台（内容 / 档案 / 学习 / 报告 / 统计 / 反馈 / 同步 / 素材）、单管理员后台、内容仓库与 Schema、四份 compose 编排与运维脚本
- ⚠️ 内容量不足：字库 83 / 古诗 3 / 单元 7 / 关卡 14 / 故事 5 / 短文 6 / 徽章 7 —— 详见 [02-4 架构演进与优化方向](./02-系统架构/04-架构演进与优化方向.md)
- ⛔ 掩藏能力（需企业主体，写契约与开关、不打包、不可达）：手机号/微信账号、支付、推送、小程序、App
- ⛔ 本期不做（设计取舍，与企业主体无关）：多角色 RBAC 后台（单管理员足够）

## 三、技术栈约定

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端（Web） | Vue 3 + TypeScript + Vite | 手机 / iPad / 桌面三档响应式 + PWA |
| 跨端内核 | **`packages/core`** | 算法 / stores / 类型 / 契约 / 开关 / 仓储接口，**零平台依赖 + 学科无关** |
| 学科包 | **`packages/subject-hanzi`** | 识字专属逻辑（不得写进 `core`） |
| 状态管理 | Pinia | 按领域拆分 store |
| 数据存储 | **MongoDB（服务端唯一真源）** | 浏览器只保留凭据与 UI 偏好，无业务数据 |
| 身份与准入 | **邀请码 + 自设密码**（Argon2id / JWT / Ed25519） | 不需要手机号与微信，**不需要企业主体** |
| 跨设备同步 | 可选云端家庭档案 + **端到端加密**（密码派生密钥，服务端只存密文） | 默认关闭、默认加密 |
| 内容分发 | **仓库内 JSON → 导入 MongoDB → `/content/*` 接口** | 内容即仓库，改内容不必发版 |
| 内容校验 | JSON Schema + CI 脚本 | 贡献者只改 JSON，CI 自动校验 |
| 后端 | Python 3.12 + **FastAPI** + MongoDB 7（motor 异步） | 单机自托管，轻职责 |
| 部署 | **Docker Compose 分服务独立编排**（mongo / api / web / admin）+ `network_mode: host` + nginx | 成本≈¥0（服务器自有） |
| 端口（默认） | Web `8080` · 管理后台 `8081` · API `8000` · MongoDB `27017` | 均在 `.env` 中可改 |
| 许可 | 代码 MIT / 内容 CC BY-SA 4.0 / 第三方许可随分发 | 见 [01-4](./01-产品规划/04-免费开放与开源策略.md) |

### 掩藏层（写代码 · 开关关闭 · 不打包 · 不部署）

| 能力 | 开关名 | 状态 |
| --- | --- | --- |
| 手机号 / 微信账号 | `enableAccountAuth` | ⛔ **需企业主体**，契约保留 |
| 支付与订阅 | `enablePayment` | ⛔ **需企业主体**，集合与契约保留 |
| 微信小程序 / iOS·Android App | `enableMiniprogram` / `enableNativeApp` | ⛔ **需企业主体**，目录与分包方案保留 |
| ICP 备案 | — | ⚠️ 取决于服务器位置：境外免备案；境内须备案（个人主体可做非经营性备案） |

> ⚠️ **两条最要紧的纪律**：
> 1. `packages/core` 中一旦出现 `window` / `document` / `uni.xxx`，跨端复用率会从 95% 掉到 0；且核心逻辑必须**与学科无关**（判据：*这段逻辑换成英语单词还成立吗？*）—— 见 [06-1](./06-工程规范/01-开发规范与前端架构.md)
> 2. **所有数据访问必须走数据仓储与 API 客户端**，禁止组件内直接读写存储 —— 这是「口径统一、可演进」的保证（见 [02-3 第二章](./02-系统架构/03-存储与后端策略.md)）

## 五、文档维护约定

1. **单一事实来源**：字段定义只在 `03-2 数据字典` 中维护，其他文档引用而非复制。
2. **契约以类型为准**：`packages/core` 中的 TS 类型是接口契约的最终事实来源，`04-1` 用于设计评审与并行开发。
3. **变更留痕**：架构或数据模型的破坏性变更通过 Git 提交信息留痕（**文档内不维护版本号与变更记录**）。
4. **命名统一**：集合名与字段名一律 `snake_case`，前端组件名用 `PascalCase`。
5. **不写空话**：文档中的每条功能描述都应能对应到一个字段、一个接口或一个页面。写不出来，说明需求还没想清楚。
6. **不写过程**：只写能指导实现的结论，不写方案对比与开发过程叙述。
7. **许可标注义务**：任何引入的第三方数据、素材、依赖，必须同步登记到 `content/sources.json` 与 `THIRD_PARTY_NOTICES.md`。**未登记来源的资产不得入库** —— 这是开源项目的法定义务。
8. **能力分级标注**：任何涉及后端、账号、支付、小程序、App 的内容，必须显式标注属于哪一类并给出能力开关名：
   - ⛔ **掩藏**（需企业主体）：手机号/微信账号、支付、小程序、App
   - ✅ **已实现**（只需服务器）：邀请码身份、云端内容后台、匿名统计、跨设备同步、云端评测
   - ⭐ **本地（非业务数据）**：会话凭据、设备标识、UI 偏好
