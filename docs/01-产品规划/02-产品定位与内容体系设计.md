# 01-2 产品定位与内容体系设计

> 本文档定义产品做什么、内容长什么样、内容怎么生产。

---

## 一、产品定位

### 1.1 一句话定位

> **跟着课本学汉字** —— 面向小学 1–6 年级的课内同步识字与古诗文启蒙工具，用游戏化方式解决"识字与遗忘"这个核心问题。

### 1.2 定位的三条边界

明确**不做什么**，比做什么更重要：

| 做 | 不做 |
| --- | --- |
| 小学课内同步识字（**课标字表 + 自编单元**） | ❌ 英语/数学等学科 |
| 古诗文启蒙与背诵 | ❌ 写作技法、阅读理解技巧 |
| 游戏化练习与复习调度 | ❌ 真人直播课、一对一辅导 |
| 家长可见的学情报告 | ❌ 硬件产品、教具 |

#### 1.2.1 扩科的边界条件

> 上表是**当前发布范围**，不是**永久边界**。产品后续**可能**增加英语、数学——但扩科有前置条件，并且**从现在起就受三条结构约束**（这三条不做，将来扩科要返工）。

| 项 | 结论 |
| --- | --- |
| **是否扩科** | 🟠 **可能，但不进当前路线图**。当前只做识字这一个点，先把它做到最好并取得用户验证 |
| **顺序（若扩）** | **语文 → 英语 → 数学**。理由不是学科热度，而是**复用发生在能力层而非学科层**：英语与语文共享"语音评测 + SRS"两条技术线；数学的判题引擎（竖式 / 步骤 / 几何）是全新重工程，复用率最低 |
| **扩科动机** | ⚠️ **只能是留存导向**（让现有用户待得更久），**不能是获客导向**。本项目免费、无收入，扩科带来的是**成本**，不是收入 |
| **启动触发条件** | ① 识字主线的内容与体验已经过真实用户验证；② 出现明确的留存需求；③ 有内容与维护资源（**一门科 = 一套内容生产 + 长期更新**） |

**从现在起生效的三条结构约束**（成本≈0，晚做则需返工）：

| # | 约束 | 落点 |
| --- | --- | --- |
| 1 | **域名学科无关** | 采用学科无关的域名，学科走 URL 路径（`/hanzi` `/english` `/math`） |
| 2 | **品牌词学科无关** | 采用不限单科的品牌词，不把「字 / 识字」写进名字 |
| 3 | **`packages/core` 学科无关** | 业务内核只放学科无关的能力（SRS / 仓储 / 能力开关 / 题型框架 / 身份）；**识字专属逻辑不得写进 core** —— [06-1 §2.9.1](../06-工程规范/01-开发规范与前端架构.md#291-packagescore-的边界) |

> **一句话**：**名字留余地，架构留余地，产品不摊开。**

### 1.3 目标用户与角色

| 角色 | 是谁 | 核心诉求 | 在系统中的位置 |
| --- | --- | --- | --- |
| **学生** | 6–12 岁小学生 | 好玩、有成就感、看得见的进度 | 学生端（主） |
| **家长** | 监督者与陪伴者 | 孩子学得怎么样、花了多少时间、掌握到什么程度 | 家长视图 + 报告 |
| **教师**（选配，二期） | 语文老师 | 布置作业、看班级掌握情况 | 教师端 |
| **内容运营** | 内部教研 | 高效地维护和扩充内容 | 管理后台 |

> **关键认知**：家长是监督者，使用主体是学生。产品必须同时满足"孩子愿意玩"和"家长看得到效果"两个条件，缺一不可。

## 二、内容体系总览

内容按四个层次组织，从下往上逐层聚合：

```
第四层  专题与计划      学习计划、单元复习、考前冲刺、古诗专题
─────────────────────────────────────────────────
第三层  古诗文内容      必背古诗、蒙学经典、诗人/朝代标注、诗意解读
─────────────────────────────────────────────────
第二层  字词句内容      汉字条目、词语、成语、例句、故事
─────────────────────────────────────────────────
第一层  字库主表        3000 个课标汉字的结构化条目（核心资产）
```

**第一层是整个产品的地基。** 它有两条消费路径：向上聚合成课程，向右归属到自编单元。

## 三、第一层：汉字字库规格

### 3.1 字量与分级

依据《义务教育语文课程标准（2022 年版）》的学段要求：

| 学段 | 年级 | 累计识字量 | 其中会写 | 本产品覆盖策略 |
| --- | --- | --- | --- | --- |
| 第一学段 | 1–2 年级 | 1600 字左右 | 800 字左右 | 精编，全部含音频与配图 |
| 第二学段 | 3–4 年级 | 2500 字左右 | 1600 字左右 | 精编，重点字含配图 |
| 第三学段 | 5–6 年级 | 3000 字左右 | 2500 字左右 | 精编，以释义与运用为主 |
| （衔接） | 幼小衔接 | 300–500 字 | 0 | 沿用现有幼儿园内容，作为引流入口 |

**总目标：3000 个精编汉字条目。**

### 3.2 单个汉字的字段规格

这是内容生产的**验收标准**，每个字都必须填满必填项才能上架：

| 字段 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `char` | ✅ | 汉字本体 | `水` |
| `pinyin` | ✅ | 标准拼音（含声调） | `shuǐ` |
| `pinyin_tone` | ✅ | 声调数字，便于评测比对 | `3` |
| `is_polyphone` | ✅ | 是否多音字 | `false` |
| `polyphone_readings` | 多音字必填 | 各读音及用法 | `[{pinyin:'shuǐ', usage:'喝水'}]` |
| `radical` | ✅ | 部首 | `水` |
| `stroke_count` | ✅ | 笔画数 | `4` |
| `structure` | ✅ | 结构：独体/上下/左右/包围 | `独体` |
| `stroke_order` | ✅ | 笔顺数据（hanzi-writer 格式） | `{data: [...]}` |
| `meaning` | ✅ | 儿童可懂的白话释义 | `喝的水，河里的水` |
| `words` | ✅ | 常用组词 3–5 个 | `['喝水','水果','河水']` |
| `sentences` | ✅ | 例句 2–3 句，贴近儿童生活 | `['我每天都要喝水。']` |
| `image_url` | ✅ | 配图（原创插画，有版权） | CDN 地址 |
| `audio_url` | ✅ | 真人标准读音音频 | CDN 地址 |
| `pictograph` | 象形字必填 | 字源演变说明 | `像流动的水` |
| `level` | ✅ | 所属学段 | `grade1` |
| `grade` | ✅ | 具体年级 | `1` |
| `unit_refs` | ✅ | **自编单元归属**（非教材映射） | 见 3.3 |
| `similar_chars` | ✅ | 形近字，用于辨析训练 | `['永','冰']` |
| `antonym` / `synonym` | 选填 | 反义/近义 | — |
| `tags` | ✅ | 主题标签 | `['自然','身体']` |
| `difficulty` | ✅ | 难度 1–5，用于出题 | `1` |
| `status` | ✅ | 上架状态：草稿/待审/已上架 | `published` |

### 3.3 单元归属设计（自编单元）

单元划分依据**主题 / 字频 / 难度**自定，数据来源为**课标字表 + 自编编排**；**不使用出版社教材目录**（教材编排涉汇编权，见 [01-4 5.3](./04-免费开放与开源策略.md#53-必须移除的高风险内容)）。「跟课本学」的需求改由**用户自定义单元**满足：家长自己勾选字组成单元。

**单元数据结构**（对应数据设计中的 `curriculum_units`）：

```json
{
  "unit_id": "u-g1-01",
  "title": "天地人（入门第一组）",
  "grade": "一年级上",
  "theme": "基础独体字",
  "character_ids": ["c_天", "c_地", "c_人", "c_你", "c_我", "c_他"],
  "focus": "入学第一组高频独体字",
  "order": 1,
  "source": "self_authored"
}
```

**单元编排的三条依据**（按优先级）：

1. **字频与难度**：先学高频、独体、笔画少的字（「一二三、人口手」）
2. **主题聚合**：自然、身体、家人、动物、数字、颜色等主题成组，便于联想记忆
3. **课标顺序**：参考《义务教育语文课程标准》的学段字量要求分配单元数量

> **「用户自定义单元」是这个问题的优雅解法**：想要「跟课本学」的家长自己勾选字组成单元（如「第三课生字」），而**项目本身不提供任何教材映射数据**——把编排权交给用户，彻底回避版权问题。这需要 P-04 自定义学习计划功能的支持。

### 3.4 内容生产工作量估算

| 环节 | 单字耗时 | 3000 字总量 | 可否并行 |
| --- | --- | --- | --- |
| 录入基础属性（拼音/部首/笔画/结构） | 1 min | 50 h | ✅ **可脚本批量导入**（拼音取 `pinyin-data`，笔画笔顺取 `hanzi-writer-data`） |
| 撰写释义与例句 | 3 min | 150 h | ✅ 可分包给教研 / 社区 |
| 组词校对 | 2 min | 100 h | ✅ 可分包 |
| 录音（真人录制或开源 TTS 批量生成） | — | 约 40 h 录音棚 | ⚠️ **素材须可开源授权**（见 [01-4 5.1](./04-免费开放与开源策略.md#51-风险分级)） |
| 配图（自绘 / CC0 / 公版古画） | 15 min | 750 h | ⚠️ 优先**自绘或 CC0**，避免未授权素材 |
| **审核与上架** | 2 min | 100 h | ❌ 需专人把关 |

> **现实建议**：不要一次做 3000 字。**先做一年级 500 字做验证**，跑通"生产 → 审核 → 上架 → 用户反馈"的完整闭环，再决定是否规模化。
>
> **开源模式下的一条关键补充**：基础属性（拼音、笔画、笔顺）**几乎零成本**——直接取白名单数据源即可（[01-4 5.2](./04-免费开放与开源策略.md#52-可用数据源白名单)）。真正需要人工的是**释义、组词、例句**这三项，而那正是最适合社区众包的部分（每个字条是独立小任务）。

## 四、第二层：词语与句子内容

| 内容类型 | 规格 | 数量目标 | 用途 |
| --- | --- | --- | --- |
| 词语 | 每个字 3–5 个常用词 | 随字库 | 组词闯关、词义理解 |
| 成语 | 含释义、出处、例句 | 300 条 | 三四年级成语积累 |
| 例句 | 每字 2–3 句 | 随字库 | 语境理解、朗读 |
| **识字短文** | **只用已学字编的短句/短文，覆盖率 ≥ 75%（口径见 [01-5 §四](./05-玩法与复习机制设计口径.md)）** | 随字库滚动扩充 | **阅读承接：认完字就有东西读得下来** |
| 故事 | 分级短文，标注目标字 | 200 篇 | 故事找字、阅读启蒙 |
| 儿歌/韵文 | 短小押韵，含目标字 | 100 篇 | 低年级朗读、记忆 |

> **识字短文与故事的分工**：故事是"有情节的读物"，长短与生字量都不受控；识字短文的唯一硬约束是**可读性**——逐篇按覆盖率筛选，只把 75% 以上是已学字的推给孩子。两者是不同的内容类型（`readings` / `stories`），校验与排序口径不同。

## 五、第三层：古诗文模块

这是当前**完全空白**、但用户明确要求补充的模块。

> ⭐ **一个好消息**：古诗的**原文**是公共领域内容（作者已故远超 50 年），且已有**成熟的 MIT 许可开源数据集**——[`chinese-poetry`](https://github.com/chinese-poetry/chinese-poetry)（37 万+ 首，含全唐诗 5.5 万、宋词 2.1 万，另含诗经、论语、蒙学经典如三字经/百家姓/千字文）。
>
> **这意味着古诗模块的原文录入成本几乎为零**，本项目只需自编「注音、短释义、赏析、玩法」，全部是自有版权内容。详见 [01-4 5.2 数据源白名单](./04-免费开放与开源策略.md#52-可用数据源白名单)。

### 5.1 内容来源与规模

| 来源 | 数量 | 说明 |
| --- | --- | --- |
| 课标推荐背诵优秀诗文 | 75 篇 | 1–6 年级必背，包含古诗词与少量文言 |
| 蒙学经典（三字经/百家姓/千字文） | 3 部 | ⭐ 数据集已含全文；**与低年级识字强契合，且公版无版权风险** |
| 拓展古诗（按主题精选） | 50–200 首 | 从 `chinese-poetry` 数据集按主题（思乡/写景/咏物）筛选 |
| 拓展名篇 | 50 首 | 经典启蒙诗（如《咏鹅》《静夜思》等低龄友好篇目） |

**首批建议做 75 首课标必背**，覆盖完整学年，形成可交付的独立模块。

### 5.2 古诗条目字段规格

| 字段 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `poem_id` | ✅ | 唯一标识 | `poem_001` |
| `title` | ✅ | 诗题 | `静夜思` |
| `dynasty` | ✅ | 朝代 | `唐` |
| `author` | ✅ | 作者 | `李白` |
| `content` | ✅ | 全文，按句切分 | `['床前明月光','疑是地上霜', ...]` |
| `pinyin` | ✅ | 逐字注音（含声调） | 与 content 等长数组 |
| `audio_url` | ✅ | 专业朗诵音频（配乐） | CDN 地址 |
| `meaning` | ✅ | 逐句白话翻译 | 与 content 等长数组 |
| `appreciation` | ✅ | 儿童版赏析，100 字以内 | — |
| `background` | 选填 | 创作背景小故事 | — |
| `key_characters` | ✅ | 诗中重点字，关联汉字主表 | `['光','月','乡']` |
| `grade` | ✅ | 建议年级 | `2` |
| `unit_ref` | 选填 | 所属自编单元 | `u-g1-01` |
| `theme_tags` | ✅ | 主题：思乡/写景/咏物/爱国 | `['思乡']` |
| `difficulty` | ✅ | 1–5 | `1` |
| `status` | ✅ | 上架状态 | `published` |

### 5.3 古诗模块的玩法设计

古诗不能只做"读一遍"，要设计成可练习的环节：

| 玩法 | 说明 | 对应能力 |
| --- | --- | --- |
| **听读** | 播放专业朗诵，逐句跟读 | 语感、记忆 |
| **填字** | 遮住关键字，从选项中选出正确字 | 字词运用（复用现有练字能力） |
| **连句** | 打乱诗句顺序，重新排列 | 语序理解 |
| **对句** | 给出上句，选择下句 | 记忆巩固 |
| **诗意配对** | 诗句与白话释义连线 | 理解 |
| **朗读评测** | 跟读打分（依赖语音能力，二期） | 发音 |

> **与识字模块的联动**：古诗中的 `key_characters` 要能反向跳转到对应的汉字字卡——这是"识字 + 古诗"两个模块的粘合点。

### 5.4 古诗内容生产工作量

| 环节 | 单首耗时 | 75 首总量 |
| --- | --- | --- |
| 录入与注音校验 | 20 min | 25 h |
| 白话翻译与赏析撰写 | 30 min | 38 h |
| 重点字关联 | 10 min | 13 h |
| 朗诵音频（专业） | — | 约 8 h 录音棚 |
| 审核 | 10 min | 13 h |

**合计约 100 人时 + 录音成本**，是一个可在一到两个月内完成的模块。

## 六、第四层：专题与计划

在字库、古诗、故事三层内容之上，组织成可执行的"计划"，直接对应家长的使用与监督需求。

| 计划类型 | 面向 | 内容组织方式 |
| --- | --- | --- |
| 每日任务计划 | 全体 | 按遗忘曲线自动排：新学 N 字 + 复习 M 字 |
| 单元同步复习 | 1–6 年级 | 按**自编单元 / 用户自定义单元**聚合字与古诗 |
| 古诗专题 | 1–6 年级 | 按主题（思乡/四季/咏物）或按年级组织 |
| 期中期末冲刺 | 各学期 | 按单元范围聚合 + 易错字专项 |
| 薄弱字专项 | 有学情数据后 | 基于个人错题自动生成 |
| 幼小衔接 | 学龄前 | 沿用现有幼儿园内容，作为低龄入口 |

现有原型中已有 14 个学习计划模板，可作为该模块的初始设计输入，但需改造为**由算法动态生成**（而非静态模板）。

## 七、内容生产的组织建议

### 7.1 生产流水线

```
字表选定 → 基础属性填充 → 释义/例句/组词撰写 → 教研一审
    → 音频录制 → 配图绘制 → 二审（音画匹配） → 上架 → 埋点反馈
```

### 7.2 角色分工

| 角色 | 职责 | 可否外包 |
| --- | --- | --- |
| 内容策划 | 定字表、定分级、定标准 | ❌ 核心 |
| 教研（语文） | 释义、例句、赏析、审核 | ✅ 可外包 |
| 配音 | 汉字标准音、古诗朗诵 | ✅ 专业外包 |
| 插画 | 配图 | ✅ 可外包 |

### 7.3 质量红线

面向儿童的内容，以下几条不可妥协：

1. **零错字**：释义、例句中的错字对儿童影响恶劣，必须双人校对。
2. **释义适龄**：不能出现超出该年级理解能力的词汇。
3. **价值观合规**：例句、故事内容需符合儿童价值观引导要求。
4. **版权清晰**：所有音频、图片必须有明确的**开源再分发授权链**。

## 八、多端内容呈现策略

同一批内容在不同端的能力不同，**内容设计必须提前按端预留呈现差异**，否则会出现"设计稿只有手机版"的返工。端清单与能力分档见 [02-2](../02-系统架构/02-多端适配与响应式设计规范.md)。

### 8.1 呈现差异矩阵

| 内容 | 手机 | iPad | 桌面 |
| --- | --- | --- | --- |
| 字卡 | 满屏单字 + 底部按钮 | **字 + 释义 + 组词 + 笔顺同屏** | 同 iPad + 辅助侧栏 |
| 学习地图 | 纵向卷轴，一期 3–4 关 | 双列网格，一期 8–12 关 | 三列 + 关卡详情侧栏 |
| 古诗 | 单栏，横排为主 | **保留竖排版式**，左诗文右注释 | 竖排版式 + 背景插画全屏 |
| 笔顺练习 | 描红跟写 | **Apple Pencil 真实书写 + 笔顺判定** | 鼠标描红 |
| 故事 | 图文分页 | 图文并排，同屏更长 | 双栏正文 |
| 学情报告 | 卡片纵向滚动 | 双图表并排 | 图表 + 明细表，可导出 |
| 跟读评测 | 声调 + 内容判定 | 同手机 | 同手机 |

### 8.2 对内容生产的硬要求

这些要求看起来是技术细节，但**必须在内容录入时满足**，事后补数据等于重做：

| 要求 | 说明 |
| --- | --- |
| **古诗必须存结构化诗句数组** | 按 `lines[]` 逐句存储，**不要存成一整段字符串**——否则 iPad 竖排版式与逐句注音都无法实现 |
| 释义长度分档 | 提供 `short`（≤ 15 字，小屏用）与 `full`（大屏用）两档 |
| 图片素材多尺寸 | 至少产出 `sm` / `md` / `lg` 三档（WebP），大屏与小屏各取所需 |
| 音频**必须提供单声道 64kbps 版本** | 手机弱网是主场景；高码率版本可选，不作为默认加载项 |
| 内容可裁剪成主题包 | 按单元/主题能独立打包，不得设计成"必须全量加载才能用" |
