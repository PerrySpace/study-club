# 01-3 功能清单与优先级路线图

> 本文档把内容体系与架构能力落成具体的功能项，并按优先级分级（P0 / P1 / P2 / R）。
>
> **前置约束**（见 [01-4 免费开放与开源策略](./04-免费开放与开源策略.md)）：不做依赖企业主体的能力、全部免费开放、项目可能开源；**已有服务器且云端后台可部署**，付费项优先用免费方案且可接受少量付费。
>
> ⚠️ **重要区分**：「需要企业主体」与「需要服务器/花钱」是两回事。**邀请码身份、云端内容后台、匿名统计、跨设备同步只需服务器，不需要企业主体**——因此它们**不进入预留池**，属于**当前已实现并部署**（见 [02-5 邀请码身份与准入体系](../02-系统架构/05-邀请码身份与准入体系.md)）。只有**手机号/微信账号、支付、小程序、App 上架**才进预留池。

---

## 一、优先级判定标准

每个功能按三个问题打分，决定它进哪一级：

1. **没有它，一个陌生的孩子能独立完成一节课吗？** —— 不能 → P0
2. **没有它，家长会继续用下去吗？** —— 不会 → P1
3. **没有它，体验会明显落后吗？** —— 不影响 → P2

| 级别 | 定义 | 判断依据 |
| --- | --- | --- |
| **P0** | 阻断级 | 缺失则产品跑不通、内容无法维护 |
| **P1** | 留存级 | 缺失则用户用完一次就不再来 |
| **P2** | 增强级 | 提升体验，但不影响核心闭环 |
| **R** | **预留级** | **依赖企业主体**（手机号/微信账号、支付、小程序、App）：代码 + 契约 + 开关保留，掩藏能力默认关闭、不打包、不可达（见 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md) 第六章） |

> ⚠️ **R 级不是 P3。** P3 是「等条件成熟再做」，R 是「现在就有意不做，但要保证将来能打开」——两者的工程动作完全不同：P3 什么都不做，R 必须写好契约、类型、开关与骨架。
>
> ⚠️ **R 级只装「需要企业主体」的能力**。需要服务器或少量付费的能力（邀请码身份、内容后台、统计、云端评测）**不进 R 级**——它们进 P0/P1/P2，但必须遵守 [01-4 2.5 的四条原则](./04-免费开放与开源策略.md#25-付费与升级能力本版本不做)。

## 二、全量功能清单

本清单列**当前发布范围**的能力（P0 / P1 / P2）；**有意不做的预留能力**（R 级，契约保留、开关关闭）见 §2.8《预留能力清单》。

| **I-12** | **端到端加密同步** | P1 | 口令派生密钥，服务端只存密文；**默认开启**，降低儿童数据合规负担 |

### 2.2 内容生产工具链

> **两层形态**：① **内容即仓库**（JSON + 校验脚本 + PR 流程）是**主路径**，零成本、Git 天然留痕；② **自托管内容后台**（单管理员）是**可选增强**——**只需服务器，不需要企业主体**，因此**不是 R 级**。**多角色 RBAC 后台属「本期不做」**（单人维护下过度设计，**与企业主体无关**），不是合规约束，故也不进 R 级。详见 [05-1](../05-管理后台/01-内容管理与用户管理体系.md)。

| C-05 | 数据来源与许可清单 | P0 | `sources.json` 逐项标注来源/许可/署名（见 [01-4 第五章](./04-免费开放与开源策略.md#五内容版权开源化的第一红线)） |

| **C-08** | **自托管内容后台（单管理员）** | **P1** | ⭐ 只需服务器：内容的在线 CRUD、批量导入、质量检查、发布。**简易口令鉴权，不做多角色** |

| C-10 | 素材托管 | P2 | 优先仓库内文件；仅在体积超限时才上对象存储 |

## 三、能力分级说明

本清单按四级组织，表示「当前必须做 / 应做 / 可增强 / 有意不做」：

| 级别 | 含义 | 典型能力 |
| --- | --- | --- |
| **P0** | 阻断级，缺失则跑不通 | 数据仓储与内容下发、邀请码身份、复习调度、开源工程化、合规与隐私底线 |
| **P1** | 留存级，缺失则留不住用户 | 云端家庭档案、学情报告、家长视图、书写与 iPad 手写 |
| **P2** | 增强级 | 语音增强、可视化内容编辑器、学习提醒 |
| **R** | 预留级，需企业主体 | 手机号 / 微信账号、支付、小程序、App（见 §2.8） |

> 当前状态见 [01-1 项目概述与定位](./01-项目概述与定位.md)；未来优化方向见 [02-4 架构演进与优化方向](../02-系统架构/04-架构演进与优化方向.md)。

## 四、核心算法：间隔重复复习调度

这是学生端的核心，单列说明。

### 4.1 为什么必须做

识字产品的本质是**与遗忘作斗争**。只做「完成关卡 → 解锁下一关」的线性推进、没有复习调度，学过的字会快速遗忘。**复习调度直接决定学习效果，也是家长最容易感知到的一环。**

### 4.2 方案

采用 SM-2 的简化变体，按字维护记忆状态：

| 状态字段 | 含义 |
| --- | --- |
| `ease_factor` | 难度系数（初始 2.5，答对升、答错降） |
| `interval` | 当前复习间隔（天） |
| `repetitions` | 连续答对次数 |
| `next_review_at` | 下次复习时间 |
| `last_result` | 最近一次结果 |

**调度规则**：

```
答对：repetitions += 1
     interval = 1（首答对） → 6（第二次） → interval × ease_factor（之后）
     每次答对 ease_factor += 0.1

答错：repetitions = 0
     interval = 1
     ease_factor -= 0.2（下限 1.3）
```

**每日任务的生成规则**：

```
每日任务 = 新学字数（按年级设定，如一年级 8 字）
         + 到期复习字（next_review_at <= 今天）
         + 错题重练（优先）
```

> **复习状态与调度由服务端计算**（见 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md) 第四章）：答题记录上报后服务端批量结算并写 `next_review_at`，客户端只渲染到期结果，保证跨设备口径一致、算法不漂移。核心调度算法是纯函数，放在 `packages/core/algorithms` 供各端复用。

### 4.3 与出题的关系

同一批到期字，用**不同题型**轮换（看图选字 / 听音选字 / 拼音匹配 / 组词），避免机械记忆。题型选择依据历史表现——一直答对的字换更难的题型。

## 五、风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **内容版权未清洁就开源** | 侵权，且 Git 历史不可撤回 | **推送公开仓库前完成来源溯源**；无法溯源的内容一律重建（[01-4 5.3](./04-免费开放与开源策略.md#53-必须移除的高风险内容)） |
| **密钥/敏感信息进入公开历史** | 无法从 fork 中撤回 | CI 强制密钥扫描；首次推送前做全历史清扫 |
| **邀请码被转发/枚举** | 超预期放量、他人访问孩子数据 | 60 bit 熵 + 口令第二因素 + `max_uses` + 限流锁定 + 码只存哈希（[02-5 第四章](../02-系统架构/05-邀请码身份与准入体系.md#四安全设计)） |
| **用户忘记口令且丢恢复码** | 云端档案无法找回 | 强制恢复码抄写 + UI 明确警告 + 导出文件兜底；**不得用"找回密码"措辞** |
| **儿童数据上云的合规义务** | 合规风险与信任风险 | **默认关闭云档案** + **默认端到端加密** + 明示告知 + 提供删除 |
| **服务器运维成为负担** | 单人维护成本上升 | 单机部署、不引 Redis/MQ、组件数压到最少；后端保持「极简单机可维护」 |
| **服务器位置选择错误** | 境内未备案被要求整改 / 境外访问慢 | 起步境外免备案；有用户量后再评估境内 + 个人备案（[02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md) 第九章） |
| 内容生产跟不上 | 有功能没内容，产品空转 | 尽早启动内容线；**内容依赖社区众包**；宁可 800 字零错误 |
| 长期只发码不开放 | 违背「免费开放」承诺 | **准入终将进入免码开放**；准入策略是阶段性手段而非长期门槛 |
| 教材数据版权风险 | 被迫返工 | **改用「课标字表 + 自编单元」**，不提供教材映射数据 |
| 换设备丢进度 | 用户流失、口碑受损 | 导出 / 导入（备份手段）+ 云端家庭档案 + 界面显式提示 |
| **数据与平台地基被推迟（I-01/X-01/I-05）** | 形态升级从「换注入」变「重写」 | 数据仓储、平台抽象、能力开关列为 P0；CI lint 禁止绕过仓储层与开关 |
| 依赖许可不兼容 | 无法合规分发 | 白名单数据源 + CI 持续扫描 + `THIRD_PARTY_NOTICES.md` |
| 维护者精力耗尽 | 项目停更 | 内容与代码分离、构建无密钥、贡献流程低门槛，保证可被 fork 续作 |
