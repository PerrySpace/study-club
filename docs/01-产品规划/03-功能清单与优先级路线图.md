# 01-3 功能清单与优先级路线图

> 本文档把内容体系和架构能力落成具体的功能项与分期排期。
>
> **前置约束**（见 [01-4 免费开放与开源策略](./04-免费开放与开源策略.md)）：不做依赖企业主体的能力、上线前全部免费开放、项目可能开源；**已有服务器且云端后台可部署**，付费项优先用免费方案且可接受少量付费。
>
> ⚠️ **重要区分**：「需要企业主体」与「需要服务器/花钱」是两回事。**邀请码身份、云端内容后台、匿名统计、跨设备同步只需服务器，不需要企业主体**——因此它们**不进入预留池**，属于**当前可做且已部署**（见 [02-5 邀请码身份与准入体系](../02-系统架构/05-邀请码身份与准入体系.md)）。只有**手机号/微信账号、支付、小程序、App 上架**才进预留池。

## 一、优先级判定标准

每个功能按三个问题打分，决定它进哪一期：

1. **没有它，一个陌生的孩子能独立完成一节课吗？** —— 不能 → 进 P0
2. **没有它，家长会继续用下去吗？** —— 不会 → 进 P1
3. **没有它，体验会明显落后吗？** —— 不影响 → 进 P2

| 级别 | 定义 | 判断依据 |
| --- | --- | --- |
| **P0** | 阻断级 | 缺失则产品跑不通、内容无法维护、或将来的迁移成本翻倍 |
| **P1** | 留存级 | 缺失则用户用完一次就不再来 |
| **P2** | 增强级 | 提升体验，但不影响核心闭环 |
| **R** | **预留级** | **依赖企业主体**（手机号/微信账号、支付、小程序、App）：代码 + 契约 + 骨架保留，能力开关关闭、不可达（见 [02-4 第四章](../02-系统架构/04-本地优先与后端策略.md#四能力开关体系前端掩藏的实现机制)） |

> ⚠️ **R 级不是 P3。** P3 是「等条件成熟再做」，R 是「现在就有意不做，但要保证将来能打开」——两者的工程动作完全不同：P3 什么都不做，R 必须写好契约、类型、开关与骨架。
>
> ⚠️ **R 级只装「需要企业主体」的能力**。需要服务器或少量付费的能力（邀请码身份、内容后台、统计、云端评测）**不进 R 级**——它们进 P0/P1/P2，但必须遵守 [01-4 2.5 的四条原则](./04-免费开放与开源策略.md#25-付费能力的四条使用原则)。

## 二、全量功能清单

本清单只列**当前排期**的能力（P0 / P1 / P2）；**有意不做的预留能力**（R 级，契约保留、开关关闭）见 §2.8《预留能力清单》。

### 2.1 本地内核与数据层（全新建设）

| 编号 | 功能 | 级别 | 说明 |
| --- | --- | --- | --- |
| I-01 | **仓储层抽象（Repository）** | P0 | 业务只依赖接口；本地实现 IndexedDB，云端实现可切换（`SyncRepository`）。**将来接后端只换注入** |

| I-04 | **进度导出 / 导入** | P0 | 无账号模式下唯一的数据保险；卸载、换设备、清缓存都会丢数据 |
| I-05 | **能力开关体系（Feature Flags）** | P0 | 三层开关（构建期/远端/用户级），默认全关。R 级能力的统一出入口 |
| I-06 | 离线数据队列 | P1 | 离线产生的记录先入队，联网后处理（阶段 B 起用于上报） |
| I-07 | 内容包加载与缓存 | P0 | 随包内容 + 远端静态覆盖（见 [02-4 3.3](../02-系统架构/04-本地优先与后端策略.md#33-内容分发四条路径)） |
| I-08 | 本地错误日志与反馈 | P1 | 无后端时可导出日志文件供用户反馈 |
| **I-09** | **邀请码注册与登入** | **P0** | ⭐ **不需要企业主体**：邀请码 + 自设口令完成注册/登入（见 [02-5](../02-系统架构/05-邀请码身份与准入体系.md)） |
| **I-10** | **离线签名邀请码校验** | P1 | Ed25519 签名，**纯前端可验**——无后端也能做邀请制；公钥随开源代码公开 |
| **I-11** | **云端家庭档案与跨设备同步** | P1 | 同一码 + 口令在任意设备恢复档案；**默认关闭，用户显式开启** |
| **I-12** | **端到端加密同步** | P1 | 口令派生密钥，服务端只存密文。**默认开启**，大幅降低儿童数据合规负担 |
| **I-13** | **恢复码机制** | P0 | 忘记口令时重置；仅显示一次、强制抄写确认 |
| **I-14** | **邀请码发放与管理** | P1 | 批量生成、用量查看、吊销；自托管后台内操作 |
| **I-15** | **准入策略开关** | P0 | 邀请制内测 / 自助领取 / 免码开放 / 纯本地，四策略可切换 |

> ⭐ **I-09 ~ I-15 是当前排期的关键能力**：它们让「注册登入 + 跨设备同步」在没有企业主体的前提下成为可能。工作量合计约 **7.5 人月**（其中约 4 人月依赖服务器），已计入 [§5.1 工作量估算](#51-当前排期)。
>
> ⚠️ **硬约束**：「先不注册」必须永远可用。**不得出现「不注册就不能用」的强制墙**——那既违背免费开放承诺，也破坏开源可运行性。

## 四、核心算法：间隔重复复习调度

这是 Phase F0 的技术核心，单列说明。

### 4.1 为什么必须做

识字产品的本质是**与遗忘作斗争**。现有原型是「完成关卡 → 解锁下一关」的线性模型，没有复习调度，学过的字会快速遗忘。**这是学习效果的最大短板，也是家长最容易感知到的问题。**

### 4.2 方案建议

采用 SM-2 的简化变体，按字维护记忆状态：

| 状态字段 | 含义 |
| --- | --- |
| `ease_factor` | 难度系数（初始 2.5，答对升、答错降） |
| `interval` | 当前复习间隔（天） |
| `repetitions` | 连续答对次数 |
| `next_review_at` | 下次复习时间 |
| `last_result` | 最近一次结果 |

**调度规则**：

```
答对：repetitions += 1
     interval = 1（首答对） → 6（第二次） → interval × ease_factor（之后）
     每次答对 ease_factor += 0.1

答错：repetitions = 0
     interval = 1
     ease_factor -= 0.2（下限 1.3）
```

**每日任务的生成规则**：

```
每日任务 = 新学字数（按年级设定，如一年级 8 字）
         + 到期复习字（next_review_at <= 今天）
         + 错题重练（优先）
```

> **全部在客户端计算**。零成本、离线可用；代价是跨设备不一致，由**导出/导入**与**云端档案同步**缓解（复习状态是追加型数据，合并时取「更晚一次」的结果即可）。算法本身是纯函数，放在 `packages/core/algorithms` 中，四端共用。

### 4.3 与出题的关系

同一批到期字，用**不同题型**轮换（看图选字 / 听音选字 / 拼音匹配 / 组词），避免机械记忆。题型选择依据历史表现——一直答对的字换更难的题型。

## 六、风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **内容版权未清洁就开源** | 侵权，且 Git 历史不可撤回 | **推送公开仓库前完成来源溯源**；无法溯源的内容一律重建（[01-4 5.3](./04-免费开放与开源策略.md#53-必须移除的高风险内容)） |
| **密钥/敏感信息进入公开历史** | 无法从 fork 中撤回 | CI 强制密钥扫描；首次推送前做全历史清扫 |
| **邀请码被转发/枚举** | 超预期放量、他人访问孩子数据 | 60 bit 熵 + 口令第二因素 + `max_uses` + 限流锁定 + 码只存哈希（[02-5 第四章](../02-系统架构/05-邀请码身份与准入体系.md#四安全设计)） |
| **用户忘记口令且丢恢复码** | 云端档案无法找回（本机数据仍在） | 强制恢复码抄写 + UI 明确警告 + 导出文件兜底；**不得用"找回密码"措辞** |
| **儿童数据上云的合规义务** | 合规风险与信任风险 | **默认关闭云档案** + **默认端到端加密** + 明示告知 + 提供删除 |
| **服务器运维成为负担** | 单人维护成本上升 | 单机部署、不引 Redis/MQ、组件数压到最少；后端只做增强，挂了不影响学习 |
| **服务器位置选择错误** | 境内未备案被要求整改 / 境外访问慢 | 起步境外免备案；有用户量后再评估境内 + 个人备案（[02-4 7.1](../02-系统架构/04-本地优先与后端策略.md#71-部署位置与备案决策)） |
| 内容生产跟不上 | 有功能没内容，产品空转 | 尽早启动内容线；**F2 后依赖社区众包**；宁可 800 字零错误 |
| 长期只发码不开放 | 违背「免费开放」承诺 | **F2 必须进入免码开放**；准入策略是阶段性手段而非长期门槛 |
| 教材数据版权风险 | 被迫返工 | **改用「课标字表 + 自编单元」**，不提供教材映射数据 |
| 换设备丢进度 | 用户流失、口碑受损 | 导出/导入（不依赖后端）+ 邀请码云档案 + 界面显式提示 |
| **地基被推迟（X-01/I-01/I-05）** | 形态升级从「换注入」变「重写」 | 三项列为 P0；CI lint 禁止绕过仓储层与开关 |
| 依赖许可不兼容 | 无法合规分发 | 白名单数据源 + CI 持续扫描 + `THIRD_PARTY_NOTICES.md` |
| 维护者精力耗尽 | 项目停更 | 内容与代码分离、构建无密钥、贡献流程低门槛，保证可被 fork 续作 |
