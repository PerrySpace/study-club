# 01-1 原型资产与重构范围

> 本文档盘点现有原型中可复用的资产、说明数据资产的真实成色，并界定重构要解决的核心结构问题与推进顺序。

---

## 一、结论先行

现有原型是一个**视觉与玩法骨架完成度很高、内容与工程底座严重不足的单机原型**。

用一句话概括当前状态：

> **它缺的不是功能，是承重结构。**

原型的每一条数据都写死在代码里，每一个用户进度都存在本地浏览器的单个 key 里。这意味着它无法支撑多档案、无法运营内容、无法沉淀学情。补功能之前，必须先立骨架。

## 三、数据资产的真实成色

这是最容易被自己人高估的地方，必须说清楚。

| 数据 | 宣称 | 实际 | 差距 |
| --- | --- | --- | --- |
| 汉字明细 | "52 个样例汉字 + 3500 条字库" | `data.ts` 中**人工精编的仅约 52 个**（有释义、组词、例句、象形提示）；`curriculum.ts` 的 3500 条中，绝大多数是从一个字表自动填充的占位记录 | 可精编上架字量 52 / 目标 3000，完成度 **1.7%** |
| 字库属性 | — | 占位字**没有**释义、没有组词、没有例句、没有音频、没有笔顺数据；拼音部分来自 `charData`，覆盖不全 | 需重新生产 |
| 故事 | "10 篇分级短故事" | 10 篇，篇幅短，未分级标注 | 需扩充至 200+ 篇 |
| 古诗 | 训练模式里提到"古诗词填字" | **全库零条古诗数据** | 从 0 开始 |
| 教材映射 | 58 个部编版单元 | ⚠️ **涉出版社汇编权，不得复用**（开源红线） | **废弃**，改由**自编单元**重建 |
| 音频 | — | 无任何真人音频，朗读依赖浏览器 TTS | 需录制或采购 |
| 配图 | 用 Emoji 代替（`imageGlyph`） | 非正式素材，**无法用于开源分发** | 需采购或绘制 |

> **核心判断**：`curriculum.ts` 里那 3500 条数据看起来"字库很全"，但它是用一个常用字表按顺序填充产生的，包含大量生僻字（如「丂」「丄」「丅」）。**它不能作为产品内容，只能作为"字的全集"来参考。** 真实的内容生产工作量被这个数字严重掩盖了。

## 四、重构要解决的三类问题

原型的短板不在功能数量，而在三层承重结构：

### 4.1 数据层没有承重结构

- 本地存储用**单个固定 key**，同一台设备上的**两个档案都无法区分**。
- **没有仓储层**：组件直接操作存储，数据访问没有统一入口；将来换存储实现要全量改代码。
- 没有导出 / 导入，卸载、换设备、清缓存即丢进度。

### 4.2 内容与代码耦合

- 所有内容硬编码在 `data.ts` / `curriculum.ts` / `supportData.ts`，**改一个字要重新构建发版**，运营无法介入。
- **占位数据混入正式数据**：自动填充的生僻字会直接出现在用户面前，严重损害信任。

### 4.3 复习调度缺失

- 进度模型是「完成关卡 → 给星 → 解锁下一关」的**线性解锁**，没有基于遗忘曲线的复习调度。
- 识字的本质是**与遗忘作斗争**，没有间隔重复（SRS）就没有真正的学习效果。

## 五、代码层面的具体技术债

给研发的同仁，以下问题在重构时必须处理：

| 问题 | 位置 | 影响 | 处理建议 |
| --- | --- | --- | --- |
| 无路由，用 `useState` 切页面 | `App.tsx` | 8 个页面已到极限，加管理后台必然失控 | 引入 Vue Router，页面级懒加载 |
| 状态全在一个 store | `useProgressStore.ts` | 单一 store 承担全部状态，无法拆分复用 | 按领域拆分 Pinia store |
| 数据硬编码 | `data.ts` / `curriculum.ts` / `supportData.ts` | 无法运营，包体积随内容线性增长 | 改为内容包加载 + 仓储层（内容即仓库） |
| 占位字库混入正式数据 | `curriculum.ts` | 用户会看到「丂」这类生僻字，严重损害信任 | 重建字库，按课标字表重新生产 |
| 单 key 本地存储 | `storage.ts` | 无法支持多档案 | 迁移至**仓储层 + IndexedDB 多档案**，后端仅作可选同步 |
| 无错误边界 | 全局 | 单点报错导致白屏 | Vue 的 `onErrorCaptured` + 全局兜底 |
| 零测试 | 全局 | 重构无安全网 | 至少覆盖 `utils/quiz.ts` 等纯函数 |
| 类型与数据脱节 | `types.ts` vs 实际数据 | 类型齐全但数据未校验 | 引入运行时校验（Zod / Pydantic） |

## 六、重构范围与推进顺序

重构不是"重写一遍"，而是**保留可复用资产、重建承重结构**：

1. **先立内核**：仓储层、能力开关、本地数据模型与多档案、导出 / 导入（对应 [01-3](./03-功能清单与优先级路线图.md) 的 I 系列）。
2. **再拆内容**：内容与代码物理分离，改由内容包 + CI 校验承载（对应 C 系列）。
3. **补算法**：间隔重复调度与每日任务（对应 S-05）。
4. **保留前端资产**：页面结构与视觉体系迁移到 Vue3（迁移路径见 [06-2 React 原型迁移方案](../06-工程规范/02-React原型迁移方案.md)）。
