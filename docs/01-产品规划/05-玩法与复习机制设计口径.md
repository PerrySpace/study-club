# 01-5 玩法与复习机制设计口径

> 本文档定义**玩法与复习机制的口径**。每条都以陈述句给出可落地的规则，并指明它解决的问题、落地在哪个文件。
>
> **依据来源**：对同类识字产品公开信息的观察（采集于 2025-10，含官方应用商店页、第三方测评与家长反馈区），要点已改写成下面可落地的口径。
>
> **前置阅读**：[01-2 内容体系](./02-产品定位与内容体系设计.md)、[03-2 数据字典](../03-数据设计/02-数据字典.md)、[05-1 内容管理与用户管理体系](../05-管理后台/01-内容管理与用户管理体系.md)。

## 一、六条硬口径

**这六条是玩法层的唯一定义处**，其他文档引用而不重复。

| # | 口径 | 解决什么问题 | 落地位置 |
| --- | --- | --- | --- |
| **G-1** | **复习必须是「提取」，不能是「重看」** | 让孩子自己选出答案，而不是再放一遍动画。重看会产生"熟悉感"的错觉，误以为记住了 | `packages/subject-hanzi/src/questions.ts`、`apps/api/app/controllers/srs.py` |
| **G-2** | **读本不能满篇生字（内容编排约定，无程序化门槛）** | 满篇生字的读本只会制造挫败；认完字必须有读得下来的东西 | 内容编排约定，见 §四 |
| **G-3** | **「已认」与「掌握」是两个数，且掌握可撤销** | 家长要能分辨"见过一面"和"已经稳了"；只按间隔判掌握，孩子要熬两个月才见涨 | `apps/api/app/controllers/srs.py` |
| **G-4** | **新字必须回头：每学 N 个新字插入一次旧字抽查** | 只推新字不回头是识字产品最常见的断裂（学完就忘） | `packages/subject-hanzi/src/stage.ts`、`apps/web/src/views/LessonView.vue` |
| **G-5** | **「看图选字」的图必须是字义联想，缺图则该题型降级** | 图不对义（或干脆没图）会把注意力从字上带走，等于白做 | `content/characters/*.json#glyph`、`apps/web/src/components/biz/QuestionCard.vue` |
| **G-6** | **玩法开关由后台下发，客户端不写死玩法表** | 玩法要能随运营调整（单次时长、题型、跟读）而无需发版 | `apps/api/app/core/runtime_config.py`、`packages/core/src/stores/site-config.ts` |

## 二、复习闭环：三层节奏（G-1 / G-4）

单靠"学新字"不构成闭环。三层节奏各管一段时间尺度：

| 层 | 时间尺度 | 内容 | 触达方式 |
| --- | --- | --- | --- |
| **L1 每日回顾** | 当天 ~ 数天 | 到期复习字 + 未清错题 | 首页"今日任务"，`GET /learning/review/due` |
| **L2 阶段检测** | 单节课内 | 本课已学过的字，反向抽查 | 每学 N 个新字插一道，`interleaveStageTests()` |
| **L3 定期复习** | 数天 ~ 数月 | SRS 排程（1 天 → 6 天 → ×ease） | `next_review_at` 到期即入 L1 |

**编排规则（L2）**：

1. **新字题的顺序原样保留**——抽查是插入，不是重排。孩子对"先学哪几个字"的预期不能被后台配置打乱。
2. **同一道题不循环复用**——抽查从"错题 → 到期复习 → 其余已学字（按 `next_review_at` 升序）"取，取尽即止。
3. **一节课最多抽查 3 次**，池子为空或本课新字不足 3 个时不强插——避免把新课上成复习课。
4. **间隔 N 由后台下发**（`gameplay.stage_test_every`），服务端 clamp 到 3–10。

> **为什么 L2 不等第二天**：L3 的第一次复习落在次日，则"当天学完就睡"这一段完全没有回头动作。L2 把一次提取塞进同一节课内，成本极低（一道题），却能立刻暴露"刚教完其实没记住"。

## 三、掌握判定（G-3）

```
掌握 ⇔ consecutive_correct ≥ 3  OR  interval_days > 60
```

| 字段 | 含义 | 变化规则 |
| --- | --- | --- |
| `consecutive_correct` | 连续答对次数 | 答对 +1；**答错归零** |
| `interval_days` | 当前复习间隔 | 走 SM-2 变体：1 → 6 → ×`ease_factor` |
| `status` | `learning` / `reviewing` / `mastered` | 由上式实时判定 |

三条必须守住的语义：

1. **双条件取或**：只按 `interval_days > 60` 判，孩子要熬两个月才看到"掌握"涨一个；只按连对次数判，长间隔的字会被蒙对提前转"掌握"。
2. **掌握可撤销**：答错即退回 `reviewing`。掌握的是**当前还稳**，不是"曾经稳过"。
3. **已认 ≠ 掌握**：只要有 `review_states` 记录就算"已认"（见过面），进 `mastered` 才算掌握。家长报告必须分列这两个数（见 §六）。

> **连对的跨天性**：因为 `consecutive_correct` 只在走 SRS 节奏时累加，3 次连对天然跨天（1 天 → 6 天），不是同一场里连点三次。

## 四、阅读承接（G-2）

**结论先行**：阅读承接由地图第三条线「**识字短文**」承担，内容类型是 `stories`
（子类型 `story` 短文 / `rhyme` 儿歌）。孩子认完字直接在这条线里读 ——
没有第二套内容类型，也没有一套按覆盖率筛选的机器。

### 4.1 编排约定

- **内容侧**：短文按「四五个句子、尽量只用已收录的字」编写；年级由内容自身的
  `grade` 字段决定，关卡按年级分桶生成。
- **产品侧**：G-2 的目标（读本不能满篇生字）**成立，但不设程序化门槛** ——
  由内容编排保证，不按覆盖率逐篇筛选。代价是质量靠人把关；好处是没有
  「覆盖率算错、把满篇生字的读本推给孩子」这个故障面。
- 若将来要把覆盖率筛选接回来，必须**一次做齐三件事**：客户端渲染 + 关卡生成改用该内容
  + 内容包登记。只做其中一处，会重演「导进去却看不见」。

### 4.2 客户端呈现

- 整篇朗读 + 逐句朗读/跟读两种读法。
- 正文三种字状态着色：**已掌握** / **已认未掌握** / **未收录**，让孩子与家长都能一眼看出"这篇里我认识几个字"。

> ⚠️ **术语易混**：`packages/core` 里的 `reading*`（跟读判定 `readingMatches`、
> 朗读速度 `readingPlanForChar/Word/Sentence`）是**语音跟读**功能，与内容类型无关。

## 五、玩法可运营（G-5 / G-6）

### 5.1 配置段 `gameplay`

**全体孩子生效**，与 `defaults`（新建档案时的初值、每人可再改）严格分工。

| 字段 | 取值 | 含义 | 消费端 |
| --- | --- | --- | --- |
| `stage_test_every` | 3–10 | 每学 N 个新字插一次旧字抽查 | `LessonView` → `interleaveStageTests()` |
| `enabled_question_types` | 题型子集 | 允许出现的题型 | 服务端 `lesson_questions()` + 客户端二次过滤 |
| `enable_speak` | bool | 跟读题型整块是否出现（同时决定是否请求麦克风） | `LessonView`、`QuestionCard` |
| `show_pictograph` | bool | 是否展示字源图 | `CharCard`、`QuestionCard` |
| `speak_rate` | 0.6–1.2 | 朗读语速，越小越慢 | 所有朗读按钮（按 `speak_rate / 0.8` 缩放） |

### 5.2 三条纪律

1. **服务端双保险**：题型过滤在服务端 `lesson_questions()` 做一次，客户端再做一次。后台能改的值不能被旧客户端绕过。
2. **不接受的输入要 clamp，不是报错**：越界值一律夹到区间内，未知题型直接丢弃，`None` 走默认值。运营参数不该让服务返回 5xx。
3. **空题型不是合法状态**：一个题型都不许 = 孩子进去没题可答。服务端回落到全集，后台前端也先挡一道。

### 5.3 字源图（G-5）

- 字段：`characters.glyph`，存象形 emoji（水 → 💧、山 → ⛰️）。**必须是字义联想**，不是任意装饰图。
- 为什么用 emoji 而不是图片：零素材成本、跨端一致、可随字库一起进 git；需要更精细的配图时再走 `image_ref` 绑定素材（两者并存，客户端优先图片）。
- 缺图时的降级：`image-choice` 题型改用释义提示出题，**不展示空白图位**。

### 5.4 语音

- 方案：浏览器原生 `speechSynthesis`（朗读）+ `SpeechRecognition`（跟读），**零成本、零密钥**，符合"优先免费方案"。
- **不给发音分数**：原生 ASR 看不见声调，打出来的分数是假的。跟读只做"有没有读出来"的反馈，不做评分。
- 语速与跟读开关都在 `gameplay` 里，家长可关（隐私上关掉即不再请求麦克风）。

#### 5.4.1 音色（不可省略）

**默认音色必须被替换，而不是照用系统默认。** 各家系统的默认中文音色差别极大，
部分设备默认就是「老式朗读机」音色 —— 机械、声调几乎听不出来，
而「听音选字」类题型完全依赖声调辨析，听不清就退化成瞎猜。

| 规则 | 说明 |
| --- | --- |
| 优选**本地**音色 | `localService` 优先：启蒙常发生在无网场合，联网音色不可用时会完全不出声 |
| 优选规则是**数据** | `VOICE_NAME_PREFERENCE` 是一组可解释的关键词（neural / enhanced / 童声命名），不是玄学；挑不中退回第一个本地音色 |
| **显式设 `utterance.lang`** | 只给 `voice` 不对齐 `lang` 时，部分内核会用错误语言的发音规则去读它 |
| 提供**本机选择**入口 | 同一台设备往往装了 2–3 个中文音色；让用户在设置里挑一次并试听，比在代码里赌一个默认值可靠 |
| 音色是**本机偏好**不是后台配置 | 它是「这台设备、这个孩子」的听感；放后台会让一台设备的难听音色影响所有人 |

> ⚠️ 音色列表是**异步就绪**的：`getVoices()` 在页面刚加载时通常返回空数组，
> 必须订阅 `voiceschanged` 事件。只在挂载时取一次，表现为「音色列表永远是空的」。

#### 5.4.2 朗读内容只取「要学的内容」

进入听一听 / 读一读 / 写一写时自动朗读，**读的是字、词、句本身，不读提示语**。
读「现在轮到你啦，点一下麦克风」这类引导语有两个害处：
延长每步等待时间，且孩子听到的是抽象指令而不是这一阶段要学的字词。

#### 5.4.3 跟读用长按启动

启动麦克风必须是**有意识的动作**：短按立即开麦时，孩子常是「想点一下看看」而非真要读，
话没说完就被判成「没读」。因此按住满 450ms、进度环走满才启动识别；
短按仍保留为直接开始。**提前松手必须明确说明为什么没开始** —— 静默无反应会被当成按钮坏了。

## 五之二、书写：看、听、读之后必须有「写」

学习流程固定为 **看一看 → 听一听 → 读一读 → 写一写** 四步。

| 步骤 | 做什么 | 为什么不能省 |
| --- | --- | --- |
| 看一看 | 字形、拼音、部首、笔画、释义、组词 | 6 岁孩子抓不住全部信息，所以拆步而不是一次摊开 |
| 听一听 | 朗读单字 | 声调是听音选字的前提 |
| 读一读 | 长按跟读 | 只听不读，练的是听觉不是口部记忆 |
| **写一写** | **米字格描红 + 笔顺** | **写是唯一能暴露字形错误的动作** —— 看和听都发现不了「把水写成氷」 |

### 5.2.1 米字格是硬要求

写字必须给田字格 + 中心十字 + 对角虚线。**没有中线参照，孩子写出来的字整体偏斜且自己看不出来**。
米字格不是装饰，是纠错工具。

### 5.2.2 笔顺没有素材时如实降级

真实笔顺需要 `character.stroke_order_ref` 指向的笔顺 JSON。
素材未入库时：给描红 + **明确告知「笔顺动画素材还没入库，先按描红练」**，
**不做假的笔顺演示**。给孩子一个编造的笔顺过程比不给更糟 ——
他会照着错误的笔顺顺序去写。

### 5.2.3 不判定「写得对不对」

笔画顺序、间架结构的判定需要图形相似度算法。本项目**只提供书写动作**，
写得像不像交给老师与家长看。给一个假的书写评分与「不给发音分数」是同一条纪律的两面。

## 六、家长报告口径（G-3）

`GET /admin/users/{account_id}/report` 与客户端报告同口径：**只给聚合值，不给逐题明细**。

| 分组 | 指标 | 说明 |
| --- | --- | --- |
| **进度** | `learned` / `mastered` / `mastery_rate` | **三个数必须同时出现**，尤其已认与掌握要分列 |
| 状态分布 | `reviewing` / `learning` / `wrong` | 复习中 / 学习中 / 待清错题 |
| 活跃度 | `streak_days` / `last_study_at` | 连续学习天数、最近一次学习 |
| 覆盖量 | `lessons` / `poems` / `badges` | 完成关卡、古诗诵读、获得徽章 |
| 质量 | `accuracy` | 答题正确率 |
| 趋势 | `trend[]`，按天 | 每日题量与正确率，窗口 1–90 天 |

**趋势图的读法**：柱高按当日**题量**归一（家长关心"练了多少"），颜色按**正确率**分档（≥80% / 60–79% / <60%）。两者分开编码，避免"练得多"和"练得对"被混成一个数。

## 七、明确不跟的做法

| 不跟什么 | 为什么 |
| --- | --- |
| 单个字 4–5 分钟、其中游戏占一半的长流程 | 吸引孩子的是游戏而非汉字。单字粒度应短，把时间留给复习与阅读 |
| 只推新字、不安排回头 | 见 G-4；这是识字产品最典型的断裂 |
| 无提醒的自动续费 | 本项目无付费，不涉及 |
| 真人课、硬件、IP 授权 | 与"免费开放 + 可自托管 + 开源"的定位互斥 |
| 会给发音打分的语音评测 | 需付费云服务且准确度存疑，与 G-1 的"提取"精神不符（假分数会误导家长） |
| 无图或图不对义的"看图选字" | 见 G-5 |
