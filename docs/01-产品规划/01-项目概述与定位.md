## 一、这是什么

一个面向**小学 1–6 年级**的**课内识字 + 古诗文启蒙**应用，用游戏化方式解决「识字与遗忘」这个核心问题。

| 项 | 内容 |
| --- | --- |
| 一句话定位 | **跟着课本学汉字** —— 小学课内同步识字 + 古诗文启蒙 |
| 目标用户 | 小学在读学生（主）、家长（陪伴与查看）、语文教师（选配） |
| 商业模式 | **免费开放**：无付费墙、无会员、无广告、无内购 |
| 身份方式 | **邀请码 + 自设密码**注册登入 —— 不需要手机号、不需要微信、**不需要企业主体** |
| 覆盖终端 | 手机 / iPad / 桌面浏览器（Web + PWA）三档响应式 |
| 数据归属 | 学习数据存**自托管服务端**；可选云端家庭档案，**默认关闭且端到端加密** |
| 许可 | 代码 **MIT** · 内容与文档 **CC BY-SA 4.0** |
| 联系 | 有疑问可邮件联系 **perry@perryspace.club** |

**技术上它是什么：** 一个 **服务端权威** 的全栈应用 —— 前端 Vue 3 PWA，后端 FastAPI + MongoDB；
内容以**仓库内 JSON**维护（改内容不必发版），导入数据库后经接口下发；需要企业主体的能力
（手机号 / 微信账号、支付、小程序、App）**写契约但默认关闭、不打包、不部署**。

---

## 二、缘起

想给孩子找个识字启蒙的应用，翻了几款都觉得差点意思 —— 广告比内容多，点两下就撞上付费墙，内容也控制不了。

既然都不合心意，那就自己写一个。于是有了这个项目。

## 三、定位

### 3.1 一句话定位

> **跟着课本学汉字** —— 面向小学 1–6 年级的课内同步识字与古诗文启蒙工具，用游戏化方式解决「识字与遗忘」这个核心问题。

### 3.2 定位的三条边界

明确**不做什么**，比做什么更重要：

| 做 | 不做 |
| --- | --- |
| 小学课内同步识字（**课标字表 + 自编单元**） | ❌ 英语 / 数学等学科（当前不做，架构留余地） |
| 古诗文启蒙与背诵 | ❌ 写作技法、阅读理解技巧 |
| 游戏化练习与复习调度 | ❌ 真人直播课、一对一辅导 |
| 家长可见的学情报告 | ❌ 硬件产品、教具 |

> **为什么不做教材映射**：教材编排涉出版社汇编权，开源项目不能携带。改用「**课标字表 + 自编单元**」，
> 「跟课本学」的需求由**用户自定义单元**满足（家长自己勾选字组成单元）。详见 [01-4 免费开放与开源策略](./04-免费开放与开源策略.md)。

### 3.3 目标用户与角色

| 角色 | 是谁 | 核心诉求 | 在系统中的位置 |
| --- | --- | --- | --- |
| **学生** | 6–12 岁小学生 | 好玩、有成就感、看得见的进度 | 学生端（主） |
| **家长** | 监督者与陪伴者 | 孩子学得怎么样、花了多少时间、掌握到什么程度 | 家长视图 + 报告 |
| **教师**（选配） | 语文老师 | 布置作业、看班级掌握情况 | 预留 |
| **内容运营** | 内部教研 / 社区 | 高效地维护和扩充内容 | 管理后台 + 内容仓库 |

> **关键认知**：家长是监督者，使用主体是学生。产品必须同时满足「孩子愿意玩」和「家长看得到效果」两个条件。

## 四、当前状态（已实现）

项目已是一个**可本地起全栈联调的可运行系统**（版本 `0.1.0`）。

### 4.1 已落地

| 模块 | 内容 |
| --- | --- |
| **学生端 / 家长端** | `apps/web`：Vue 3 + Vite + Pinia + PWA；手机 / iPad / 桌面三档响应式；学习地图、字卡、闯关、每日任务、复习、错题本、古诗、故事、学情报告、设置 |
| **云端后台** | `apps/api`：Python 3.12 + FastAPI + MongoDB 7；内容读取、邀请码身份、儿童档案、学习与复习、学情报告、匿名统计、反馈、素材托管、可选加密同步 |
| **管理后台** | `apps/admin`：Vue 3 + Element Plus；单管理员；概览、邀请码、字库、古诗、短文、用户、配置 |
| **内容仓库** | `content/`：JSON + JSON Schema + `sources.json`；`scripts/seed` 按表导入 MongoDB |
| **部署** | `deploy/`：mongo / api / web / admin 四份独立 compose（host 网络）+ nginx 同源反代；`scripts/` 运维脚本 |
| **跨端内核** | `packages/core`（零平台依赖 + 学科无关）、`packages/subject-hanzi`（识字专属）、`packages/tokens`（设计变量） |

### 4.2 内容规模（当前）

| 类型 | 条数 |
| --- | --- |
| 汉字 | 83 |
| 古诗 | 3 |
| 单元 | 7 |
| 关卡 | 14 |
| 故事（孩子端地图第三条线「识字短文」，含儿歌） | 5 |
| 徽章 | 7 |

> ⚠️ **内容量是当前最大的短板**。系统设计已支撑规模化，但内容尚未达到可用规模 —— 扩容方向见 [02-4 架构演进与优化方向](../02-系统架构/04-架构演进与优化方向.md)。

### 4.3 技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Pinia + vue-router + PWA |
| 跨端内核 | `packages/core`（算法 / stores / 类型 / 契约 / 开关 / 仓储接口，零平台依赖 + 学科无关） |
| 学科包 | `packages/subject-hanzi`（拼音比对、题型生成、跟读判定） |
| 设计变量 | `packages/tokens`（三档断点 / 触控热区 / 色彩） |
| 后端 | Python 3.12 + FastAPI + MongoDB 7（motor 异步） |
| 身份与准入 | 邀请码 + 自设密码（Argon2id 密码 / JWT 会话 / Ed25519 邀请码签名） |
| 内容分发 | 仓库内 JSON → 导入 MongoDB → `/content/*` 接口 |
| 部署 | Docker Compose 分服务独立编排 + `network_mode: host` + nginx |

> 详细的选型理由见 [02-1 系统总体架构与技术选型](../02-系统架构/01-系统总体架构与技术选型.md)。

## 五、六条前置约束（决定一切）

这六条是项目的硬约束，任何方案都必须满足。**这是六条约束在全套文档中的唯一定义处**，其他文档引用而不重复：

1. **不做需要企业主体的能力** —— 不做手机号/微信账号、支付、小程序、App 上架、短信
2. **全部免费开放给所有用户** —— 不向用户收费
3. **项目开源** —— 贡献者必须能零成本、零密钥地克隆运行
4. **可自托管** —— 后端运行在自有服务器上，只做「轻」职责（内容管理、匿名统计、邀请码校验、可选同步）
5. **内容与代码分离** —— 内容以仓库 JSON 维护，改内容不必发版
6. **付费项优先用免费方案，少量付费可接受** —— 付费能力必须可选、可降级、默认关闭

**由此推出架构**：**服务端权威 + 内容即仓库 + 单机自托管后端 + 企业能力掩藏**。

```
不做企业主体的事 ──┐
                   ├──► 手机号/微信账号、支付、小程序、App → ⛔ 写代码但不启用（掩藏）
全部免费开放 ──────┤
                   ├──► 不收费 → 成本须极低，优先免费方案
可自托管 ──────────┤
                   ├──► ✅ 后端真实上线：内容读取 · 邀请码校验 · 匿名统计 · 可选同步
内容与代码分离 ────┤
                   ├──► 内容即仓库，改内容不必发版
少量付费可接受 ────┤
                   └──► ✅ 付费服务可用，但必须可选可降级
项目开源 ──────────┘
                       └──► 克隆后不配密钥、不付费也要能跑起来
```

> ⚠️ **最关键的一条区分**：**「不做企业主体的事」不等于「不能有服务器」**。
>
> | 类型 | 例子 | 处理 |
> | --- | --- | --- |
> | **要企业主体** | 手机号/微信账号、支付、小程序、App 上架 | ⛔ 掩藏 + 契约预留 |
> | **只要服务器或少量花钱** | **邀请码身份**、云端内容后台、匿名统计、跨设备同步、云端评测 | ✅ **可做且已实现** |
> | **都不需要** | 会话凭据、设备标识、UI 偏好 | ⭐ 浏览器本地 |
