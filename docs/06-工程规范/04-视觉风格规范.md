# 06-4 视觉风格规范

> 本文档定义 study-club 的视觉风格与设计约束。
>
> **它解决什么问题**：本项目同一时期内产出过三种互不兼容的视觉语言 ——
> 单色描边图标、emoji 插画、彩色圆润的 Canvas 地图。三者各自都不难看，
> 但放在一起明显不像同一个产品，且**没有任何规则说明为什么该用哪种**。
>
> **本文档的定位**：不是「审美建议」，而是**可判定的硬规则**。
> 每条规则都写成能回答「这个对还是错」的形式，评审时逐条对照，不靠感觉争论。
>
> 配套：色值与间距的**唯一来源**是 `packages/tokens/src/tokens.css`（勿在组件中重复定义）；
> 本文档定义**语义**与**用法约束**，不重复定义色值本身。

---

## 零、定位与设计前提

在定规则之前，先说清「为谁设计」，否则规则无从判断对错。

| 维度 | 事实（来源：README「这是什么」） |
| --- | --- |
| 主用户 | 小学 1–6 年级学生（约 6–12 岁） |
| 第二读者 | 家长（陪伴与查看） |
| 使用场景 | 家庭自学，**家长在旁边**、孩子自己点 |
| 产品主张 | 免费开放、本地优先、可自托管 |
| 内容范围 | 课内识字 + 古诗文启蒙 |

由此推出三条**不可违背的设计前提**（后续所有规则都是它们的推论）：

1. **孩子要能自己完成操作。** 不识字的孩子读不懂文字指令，所以图形必须先于文字承担识别任务。
2. **家长在旁边看。** 任何界面都不能只考虑「好玩」——家长需要一眼看出「学到哪了、今天做了什么」。
3. **6–12 岁跨度过大。** 低年级与高年级的识字水平、专注时长、手部精细动作差异极大，
   因此**视觉语言必须靠形状与位置建立层级，而不是靠字号与颜色数量的差异**。

---

## 一、形状：一切皆圆，无尖角

> **规则 1.1**：所有**可交互元素**必须使用圆角，`--radius-pill`（999px）为默认。

按钮、关卡节点、图标底、标签、选项卡头 —— 一律圆形或胶囊形。

> **规则 1.2**：24 视窗的图标内部**不得出现尖角**。

尖角（直角三角形、锐角折线）在儿童界面会显得生硬、与整体柔和调性冲突。
画图标时所有描边必须带 `stroke-linecap="round"` / `stroke-linejoin="round"`。

> **规则 1.3**：卡片圆角不得小于 `--radius-md`（12px）。

**理由**：儿童认知里「圆的东西可以按、尖的东西戳手」，圆润形状天然传达「可亲近、可操作」。
这是儿童界面设计中被反复验证的结论，不是偏好问题。

**例外**：进度条、输入框的边框等非交互装饰元素不受 1.1 约束。

---

## 二、颜色：语义绑定，禁止装饰

> **规则 2.1**：颜色**必须**绑定语义。同一语义在全局只能有一个色值。

| 语义 | 令牌 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| 已完成 | `--color-success` 绿 | 孩子做完了 | 已学字、已闯关、掌握徽章 |
| **未做（还没到）** | `--color-border` / 中性灰 | **还没解锁、还没开始** | 未解锁的关卡、未开始的单元 |
| 正在进行 | `--color-info` 蓝 | 当前所在 | 当前关卡、进行中的题目 |
| 可行动 | `--color-primary` 黄 | **现在可以点** | 主行动按钮、当前可点的关卡 |
| 需要注意 | `--color-warn` 橙 | 有问题要处理 | 错题、即将到期的复习 |

> **规则 2.2**：⚠️ **未解锁/未开始的元素用灰色，不用主色。**
>
> 这条是本次规范最容易被违反、后果最明显的一条。
>
> **反例**：把未解锁的关卡画成主色黄。
> 孩子会以为「黄色=可以点」，结果点了没反应 —— 这是**教给孩子一个错误的映射**，
> 之后每加一个黄色元素，这个映射就再被强化一次。
>
> **正例**：未解锁 = 灰（`#dfe8e2` 系），可点 = 黄。映射唯一且稳定。

> **规则 2.3**：单个组件内**最多使用 2 个语义色**。

三个及以上颜色会让「什么最重要」变得不确定。孩子界面必须让主行动一眼可辨。

> **规则 2.4**：⛔ **禁止用 `currentColor` 作为图形主体色。**

`currentColor` 会让图形各自继承所在位置的文字色，导致色相不可控 —— 这正是本项目
图标风格分裂的根因（曾经全部图标都是 `currentColor` 的单色描边，与彩色地图割裂）。
图形颜色必须**显式指定**或用语义令牌。

**判定方法**：把界面截图转成灰度，如果仍能分辨出「哪个是主行动」，说明颜色用对了；
如果只能靠猜，说明颜色承载了过多含义。

> **规则 2.5**：导航（侧栏 / 底栏）只有**两态**：未选中 = 中性灰，当前 = `--color-info` 蓝底。
>
> 图标自带的彩色是**图形识别色**（每个入口一个，让不识字的孩子靠形状与颜色认入口），
> 不是状态语义色；状态一律由**底色与字重**表达，所以未选中项要把图标降为灰（grayscale）。
> 这样导航里始终只有两个语义色（灰 / 蓝），规则 2.3 才立得住。

> **规则 2.6**：星星是**奖励**语义，不是状态语义。
>
> 点亮用 `--color-primary-strong`（金），未点亮用 `--color-border`（中性灰）。
> ⛔ 未点亮的星星**不能**用彩色描边 —— 否则「灰的那颗」会被读成另一种状态，
> 而不是「还没得到」（与规则 2.2 同理）。

## 三、图形：自绘优先，emoji 限位

> **规则 3.1**：**正式图形必须自绘 SVG 或 Canvas**，不使用 emoji。

emoji 在 Windows / iOS / Android / 各浏览器上渲染各不相同 —— 同一个 📖 在三端是三个样子，
且无法控制尺寸、颜色与描边。这是**跨端一致性的直接威胁**，而本项目必须三端一致。

> **规则 3.2**：emoji **只允许**出现在「临时占位插画」位置，且必须：
> 1. 包在固定尺寸的圆形容器内（保证视觉尺寸稳定）；
> 2. 旁边必有文字标签（emoji 绝不能是唯一的信息来源）；
> 3. 集中在**一处**定义，便于将来整体替换为正式素材。

现有的三块知识块插画（📖 🏮 🌳）即属此类 —— 它们是**明确的占位**，
将来有正式插画时只需替换这一处。

> **规则 3.3**：图标 sprite 的每条路径**只用纯色填充**（不用 `currentColor` 描边），
> 且每个图标自带**圆形浅色底**。

这使图标与地图的关卡节点（圆底 + 高光 + 投影）在视觉上同属一套语汇。
详见 `apps/web/public/icons.svg` 文件头的设计规范注释。

> **规则 3.4**：星星必须**自绘**，不用 ★ / emoji。
>
> ★（U+2605）在部分安卓与 Windows 字体里会被替换成彩色字形或宽度不一致的符号，
> emoji ⭐ 更是三端三个样。而星星是「我做得怎么样」的**唯一反馈** ——
> 它的形状与颜色必须处处一致。统一实现见 `components/biz/StarRow.vue`。

## 四、场景插画色板（Canvas 与插画专用）

> **规则 4.1**：场景色必须**上收为令牌**，禁止硬编码在组件里。

本项目的学习地图（Canvas 绘制）已定义了若干颜色，但目前是**硬编码**在组件内的
（草地 `#dff0c8`、当前蓝 `#7ec8ff`、完成黄 `#ffd166`）。这意味着改主题要翻组件代码，
是明确的设计债。

已落地为令牌（值与早期实现不同处见下方说明）：

```css
:root {
  /* ---- 场景色板（Canvas / 插画**装饰**专用）----
     ⚠️ 装饰部分不承载语义；但「节点状态」是例外 —— 它承载的是规则 2 的状态语义，
        因此这几个值与 --color-success / --color-info 保持同色系。
        状态色请优先用语义令牌；只有在需要渐变/描边等派生值时才用这里。 */
  --color-scene-sky: #dff0c8;         /* 草地渐层·上 */
  --color-scene-grass: #bcdc9c;       /* 草地渐层·下 */
  --color-scene-path: #f2f7e4;        /* 赛道路面 */
  --color-scene-path-edge: #96be6e;   /* 赛道描边 */
  --color-scene-trail-done: #7ed6a3;  /* 已走过的路面（绿） */
  --color-scene-node-done: #4ec98a;   /* 节点·已完成（绿） */
  --color-scene-node-done-edge: #2f9e69;
  --color-scene-node-current: #7ec8ff;      /* 节点·进行中（蓝） */
  --color-scene-node-current-edge: #3a86ff;
  --color-scene-node-locked: #b9c4ad;       /* 节点·未解锁（灰） */
}
```

> ⚠️ **已发生过的一次修正**：节点「已完成」原本用主色黄（`#ffd166`），
> 与规则 2 的「绿 = 已完成」冲突 —— 主色黄要留给「可行动」。
> 一个元素同时表达两种语义，等于两种都不是。现已统一为绿。

> **规则 4.2**：场景装饰**不得承载信息**。

装饰（树、花、云、草地渐层）的唯一作用是营造氛围。
⛔ 不允许「只有装饰能区分的关卡状态」—— 状态必须由节点本身的颜色、图标、边框表达。
否则关闭装饰的降级模式下（`prefers-reduced-motion` 或低端机）信息就丢了。

> **规则 4.3**：装饰位置必须**确定性生成**，禁止 `Math.random()`。

同一个内容 id 必须永远长在同一个位置。用随机数会导致每次进页面装饰跳位，
孩子会感觉「地图在动」，且**视觉回归测试无法稳定**。
做法见 `packages/core` 的 `seeded()`（由 id 派生的伪随机）。

## 五、动效：表达因果，不表演

> **规则 5.1**：动效必须**回答一个因果问题**：「什么变成了什么」。

✅ 正例：节点逐个出现（表达「关卡是依次解锁的」）；当前关呼吸光晕（表达「这里可以点」）。
❌ 反例：按钮放大缩小、装饰飘动 —— 不携带任何信息，只增加等待。

> **规则 5.2**：必须尊重 `prefers-reduced-motion`。

开启时直接呈现最终状态，不做入场动画。这是可访问性底线，不是可选项。
参照 `TrackCanvas.vue` 的 `reduceMotion` 处理。

> **规则 5.3**：动效时长 ≤ 600ms，且**不得阻塞下一次可交互**。

超过 600ms 的等待在儿童端是明显的耐心成本。全局入场动画建议 400–600ms。

---

## 六、层级：用形状与位置，不用颜色数量

> **规则 6.1**：界面层级**优先**用留白、容器、位置表达，颜色只做辅助。

6–12 岁跨度过大（前提 3），不能用「字号更大 + 颜色更多」来区分层级 ——
低年级孩子读不了小字，高年级孩子又觉得幼稚。用留白与容器区分层级，两端都能读。

> **规则 6.2**：⛔ **禁止在页面里使用 emoji 作为「装饰性标题」或「分区图标」**。

分区标题请用文字或规则 3.1 的自绘图标。装饰性 emoji 会让页面显得廉价，
且与「正式图形自绘」的规则冲突。

## 七、可访问性底线（WCAG AA）

> **规则 7.1**：点击热区 ≥ 56px（`--tap-min`）；主行动 ≥ 64px（`--tap-primary`）。

儿童手指精细动作不成熟，且屏幕密度差异大。**热区不小于视觉尺寸的 1.5 倍**是常见做法。

> **规则 7.2**：正文对比度 ≥ 4.5:1，大字与图形 ≥ 3:1。

> **规则 7.3**：**Canvas / 图形化的内容必须提供 DOM 替代**。

Canvas 对键盘与读屏是黑盒。参照 `TrackCanvas.vue` 的做法：
画布 `aria-hidden`，而**每个关卡是一个真实的 `<button>`**，绝对定位覆盖在画布上，
尺寸与画布圆盘一致。这样能 Tab、能被读屏念出「第 3 关 动物 10（未解锁）」。

> **规则 7.4**：所有图标按钮必须有可访问名称（`aria-label` 或视觉隐藏文本）。

纯图标按钮对读屏是不可见的。

## 八、评审清单

新增或修改界面时，逐条对照：

- [ ] 所有可交互元素是圆角，无尖角（规则 1.1 / 1.2）
- [ ] 未解锁元素是**灰色**，不是主色（规则 2.2）
- [ ] 单个组件内语义色 ≤ 2 个（规则 2.3）
- [ ] 没有把 `currentColor` 用作图形主体色（规则 2.4）
- [ ] 导航只有「未选中灰 / 当前蓝」两态，图标未选中已降灰（规则 2.5）
- [ ] 星星自绘、未点亮是中性灰（规则 2.6 / 3.4）
- [ ] 没有用 emoji 承载唯一信息；占位 emoji 包在固定容器内且有文字标签（规则 3.2）
- [ ] 场景色走令牌，不硬编码（规则 4.1）
- [ ] 装饰不承载信息（规则 4.2）
- [ ] 装饰位置确定性生成（规则 4.3）
- [ ] 尊重 `prefers-reduced-motion`（规则 5.2）
- [ ] 点击热区 ≥ 56px（规则 7.1）
- [ ] 画布类图形有 DOM 替代、可键盘访问（规则 7.3）
