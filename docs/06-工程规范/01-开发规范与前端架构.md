# 06-1 开发规范与前端架构

> 本文档定义代码组织方式与编码约定，保证多人协作时代码风格与结构一致。
>
> ⚠️ **两条贯穿全文的硬约束**（来自 [01-4](../01-产品规划/04-免费开放与开源策略.md)、[02-3](../02-系统架构/03-存储与后端策略.md)）：
> 1. **零密钥、零付费依赖（主流程）**：任何需要 Key 或付费服务的能力，必须是可选、可降级、默认关闭的增强；贡献者克隆后不配密钥也能完整跑通。
> 2. **服务端权威 + 能力掩藏**：学习数据、儿童档案、内容全部存服务端 MongoDB，所有数据访问走仓储 / API 客户端；需企业主体的能力（账号实名、支付、小程序、App）代码存在但**不打包、不可达、不可调**。

### 2.2 状态管理划分

领域状态**必须按领域拆分**，不采用单一全局 store：

| Store | 职责 | 存储 |
| --- | --- | --- |
| `auth` | 登录态、会话 Token、邀请码身份 | 服务端（Token 由 `sc.session` 承载） |
| `child` | 当前儿童档案、学习设置 | 服务端（MongoDB） |
| `content` | 字库 / 古诗 / 单元等全量内容（`GET /content/bootstrap` 一次拉取） | 内存；真源在服务端 |
| `learning` | 当前学习会话、答题进度、临时状态 | 服务端提交；本地仅存会话级临时状态 |
| `review` | 待复习队列、SRS 状态 | 服务端（MongoDB） |
| `site-config` | 站点运行配置（玩法开关、默认学习目标） | 服务端（MongoDB 单文档） |
| `ui` | 弹窗、Toast、加载态 | ❌ 纯内存 |

**位置约定**：`auth` / `child` / `content` / `learning` / `review` / `site-config` 属**领域状态**，放在 `packages/core/stores`（跨端共用）；仅 `ui` 属外壳特有状态，放在 `apps/web/src/stores`。

**原则**：

- **服务端是唯一真源**：学习数据、档案、进度、复习状态全部存服务端 MongoDB；浏览器不持有任何业务数据，localStorage 只承载四类非业务键（见下）。
- **所有数据访问必须走仓储 / API 客户端**：store 内**禁止**直接 `localStorage.setItem` 或自行发请求，一律通过 `ApiRepository` 与 `packages/core/api` 客户端（见 [2.8](#28-能力开关与仓储层规范)）。
- **UI 状态与业务状态分离**：弹窗开关不放业务 store。
- **导出使用 `storeToRefs`**：在组件中保持响应性。

**`localStorage` 白名单（只允许这四类键，实现在 `apps/web/src/platform/storage.ts`）**：

| 键 | 内容 | 为什么允许 |
| --- | --- | --- |
| `sc.session` | 会话 Token | 路由守卫在首个 tick 就要同步判断登录态，异步存储会闪一下登录页 |
| `sc.currentChild` | 当前档案的纯 UI 偏好 | 丢了最多重选一次，不含任何学习记录 |
| `sc.deviceId` | 本机设备随机 id | 登录时上报，让「同一账号的多台设备」各持独立会话（多地同时登入的前提） |
| `sc.loginMemory` | 登入页「记住账号与口令」 | 用户主动勾选才写；只存本机、不上传；取消勾选或登出即清 |

> ⛔ 这四类键**均不含业务数据** —— 学习数据的真源在服务端 MongoDB，任何「以本地为主存储」的新键都属于违规。

### 2.3 组件规范

| 约定 | 规则 |
| --- | --- |
| 命名 | 组件文件 `PascalCase.vue`；组合式函数 `useXxx.ts` |
| 组件类型 | `base/` 纯展示无业务；`biz/` 含业务逻辑；`views/` 对应路由 |
| Props | 必须声明类型与默认值，布尔型默认 `false` |
| 事件 | 用 `defineEmits` 显式声明，命名用 `kebab-case` 或 `update:modelValue` |
| 插槽 | 多插槽需具名，提供默认内容 |
| 大小 | **单文件超过 300 行须拆分** |
| 副作用 | 统一在 `onMounted` / `watch` 中管理，配 `onUnmounted` 清理 |

### 2.5 接口层封装

```ts
// packages/core/src/api/client.ts —— 要点
// 1. 统一 baseURL 与超时
// 2. 请求拦截：注入 Authorization
// 3. 响应拦截：统一解包 { code, data }，非 0 抛业务异常
// 4. 401 自动刷新 Token 并重试一次（防止并发重复刷新）
// 5. 网络异常统一提示，不逐处 try/catch
```

**错误处理约定**

| 场景 | 处理方式 |
| --- | --- |
| 业务错误（code ≠ 0） | 抛 `BizError`，由调用方按需提示 |
| 401 Token 过期 | 拦截器静默刷新并重试 |
| 401 刷新失败 | 清除登录态，回到登录页 |
| 403 能力未开启 | 抛 `FeatureDisabledError`（见 [2.8](#28-能力开关与仓储层规范)），**不提示"请升级"** |
| 网络错误 / 后端不可达 | 抛 `NetworkError`，UI 展示可重试的错误态（后端为必需依赖，不静默降级成空数据） |
| 5xx | 提示"服务繁忙"，写本地日志（**不接 Sentry 云**，见 2.7） |

> ⚠️ **免费模式下所有用户能力一致，不存在「未开通」状态**。任何「因权限不足而跳转到不存在的外链入口」的旧逻辑都必须删除——把用户导向一个不存在的页面，比不提示更糟。

### 2.6 网络与缓存要点

内容与学习数据以服务端为准，客户端做的是「少发请求、失败可重试」：

| 要点 | 说明 |
| --- | --- |
| 内容一次拉取 | 登录后 `GET /content/bootstrap` 一次拿到全量内容，之后走内存，不逐接口分页 |
| 提交带客户端 ID | 作答提交带 `client_record_id`，服务端按 ID 去重 |
| 批量补报 | 提交失败时本地入队，恢复联网后批量上报，服务端按 ID 去重 |
| 素材缓存 | 音频 / 图片走 Cache Storage，设上限并 LRU 淘汰（PWA 静态资源缓存） |
| 声调评测 | F0 提取在客户端执行，实时反馈无需往返服务端 |

### 2.8 能力开关与仓储层规范

这两套机制是「服务端权威 + 内容即仓库 + 企业能力掩藏」在代码里的唯一落点。完整设计见 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md)，本节只定编码规则。

#### 2.8.1 能力开关（Feature Flag）

**定义位置**：`packages/core/src/flags`。**开关名与默认值的唯一权威清单以该目录为准则**，见 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md)，此处不重复维护。

```ts
// packages/core/src/flags/index.ts —— 要点
export interface FeatureFlags {
  enableInviteAuth: boolean;          // 邀请码身份（默认开）
  enableInviteRequired: boolean;      // 强制凭码注册（默认开）
  enableInviteOfflineVerify: boolean; // 邀请码离线签名校验（默认开）
  enableCloudProfile: boolean;        // 云端家庭档案与跨设备同步（默认关）
  enableE2EEncryption: boolean;       // 端到端加密同步（默认开）
  enableContentApi: boolean;          // 后端内容接口（默认开）
  enableStats: boolean;               // 匿名统计上报（默认开）
  enableCloudAssessment: boolean;     // 云端语音评测（可选，默认关，无 Key 整块隐藏）
  enableAccountAuth: boolean;         // ⛔ 手机号 / 微信账号
  enablePayment: boolean;             // ⛔ 支付与订阅
  enableMiniprogram: boolean;         // ⛔ 微信小程序
  enableNativeApp: boolean;           // ⛔ iOS / Android App
}
// 构建期用 Vite define 静态求值，以支持死代码消除
```

**三条编码纪律**：

| # | 规则 | 理由 |
| --- | --- | --- |
| ① | 开关值**只读一次**（启动时求值），运行中不散落读取 | 避免同一构建出现不一致状态 |
| ② | 关闭的能力：**路由不注册 + 组件不渲染 + API 抛 `FeatureDisabledError` + 类型保留** | 四道防线，见 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md) |
| ③ | **禁止伪隐藏**：不得用 CSS `display:none`、隐藏入口但接口可调 | 前端隐藏不是权限控制 |

> ⛔ **`enablePayment` 关闭时，「按权限跳转外部入口」之类的代码路径必须一并从产物中消除**（死代码消除），而不是留一个永远走不到的页面。

#### 2.8.2 仓储层（Repository）

**唯一数据出入口**：业务代码（store / 组件 / 组合式函数）**只依赖仓储接口与 API 客户端**，实现由 `packages/core/repositories` 与 `packages/core/api` 提供。

```ts
// ✅ 正确：通过注入的仓储（唯一实现 ApiRepository，落点为服务端 MongoDB）
const repo = useCore().repositories.progress;
await repo.submitAnswer(input);

// ❌ 禁止：绕过仓储 / API 客户端直接读写存储或发请求
localStorage.setItem('progress', JSON.stringify(p));
await fetch('/api/v1/...');
```

**ESLint 强制**（CI 阻断）：

```js
{
  files: ['packages/core/**/*.ts', 'apps/*/src/{stores,views,components,composables}/**/*.{ts,vue}'],
  rules: {
    'no-restricted-globals': ['error',
      { name: 'localStorage', message: '请走 platform 存储适配器，业务代码勿直连存储' },
      { name: 'fetch',        message: '请通过 packages/core/api 客户端发请求' },
    ],
    'no-restricted-imports': ['error', {
      patterns: ['**/platform/**'],  // 平台实现只允许在 platform 目录内被 import
    }],
  },
}
```

**实现分层**：

| 实现 | 状态 | 说明 |
| --- | --- | --- |
| `ApiRepository` | ✅ 当前唯一实现 | `ProgressRepository` 的服务端实现，落点为 MongoDB（`packages/core/repositories/remote.ts`） |
| `HttpSource` | ✅ 当前唯一内容源 | 登录后从 `/content/bootstrap` 一次拉全量内容（`packages/core/repositories/content.ts`） |
| 注入切换 | — | 业务代码只依赖接口，换实现不改业务 |

### 2.9 跨端与多端约定（红线）

本节是**架构级纪律**，违反会让 `packages/core` 失去复用价值。终端形态与降级规则见 [02-2](../02-系统架构/02-多端适配与响应式设计规范.md)。

#### 2.9.1 `packages/core` 的边界

| 允许 | 禁止 |
| --- | --- |
| 纯 TS 函数、类型、常量、枚举 | `window` / `document` / `navigator` |
| Pinia store（领域状态） | `localStorage` 等任何浏览器 / 平台存储 API |
| 通过接口调用平台能力 | 直接 `import` 某个 HTTP 库自行发请求 |
| 依赖注入、工厂函数、纯算法 | 任何 `.vue` 模板、样式、UI 组件 |
| 数据转换、校验、计算 | 依赖具体外壳的实现细节 |
| **学科无关**的业务逻辑（SRS、题型框架、仓储、能力开关、身份、报告口径） | **识字专属逻辑**（字库 / 笔顺 / 拼音 / 象形 / 单元组织） |

> ⚠️ **第二条红线：学科无关。** `core` 不只"与平台无关"，还必须"**与学科无关**"——因为产品后续**可能增加英语、数学**（见 [01-2 §1.2.1](../01-产品规划/02-产品定位与内容体系设计.md#121-扩科的边界条件)）。判据只有一句：
>
> **「这段逻辑换成英语单词还成立吗？」** 成立 → 属 `core`；不成立 → 属学科包（如 `packages/subject-hanzi`）。
>
> 这条从第一天写下来几乎是零成本；等 `core` 里塞满字库与笔顺代码再拆，代价是重写整个前端。

**CI 强制**（`eslint.config.js`，`packages/core` 目录生效）：

```js
{
  files: ['packages/core/**/*.ts'],
  rules: {
    'no-restricted-globals': ['error',
      { name: 'window',   message: 'core 必须保持平台无关，请通过平台能力接口注入' },
      { name: 'document', message: 'core 必须保持平台无关' },
      { name: 'navigator',message: 'core 必须保持平台无关' },
      { name: 'localStorage', message: 'core 必须保持平台无关，请用 platform 接口' },
    ],
    'no-restricted-imports': ['error', {
      patterns: ['**/apps/**'],
    }],
  },
}
```

#### 2.9.2 平台能力注入

业务代码**唯一**获取平台能力的入口是 `usePlatform()`：

```ts
// ✅ 正确
const { recorder, capabilities } = usePlatform();
if (capabilities.canRealtimeAudioAnalysis) { /* 实时曲线 */ }
else { /* 录后分析（降级路径） */ }

// ❌ 禁止：在 core 里探测平台
if (/Android/i.test(navigator.userAgent)) { ... }
```

- 平台差异**只允许**出现在 `apps/*/src/platform/` 内
- 每个能力缺失**必须同时提供降级路径**，不允许只隐藏入口（见 [02-2 §七](../02-系统架构/02-多端适配与响应式设计规范.md#七能力探测与降级)）

#### 2.9.3 响应式编码约定

| 约定 | 规则 |
| --- | --- |
| 断点来源 | 只能引用 `packages/tokens` 的断点常量；**禁止在组件里写 `window.innerWidth > 900`** |
| 断点数值 | 手机 `<768` / 平板 `768–1279` / 桌面 `≥1280px` |
| 触控热区 | 最小 `--tap-min: 56px`，主操作 `--tap-primary: 64px`；相邻热区间距 ≥ 12px |
| 安全区 | 底部固定元素用 `env(safe-area-inset-bottom)`；全屏用 `100dvh` 而非 `100vh` |
| hover | 一律包在 `@media (hover: hover)` 内（触屏上 `:hover` 会粘住） |
| 大屏 | 内容区受 `--content-max: 880px` 约束；**大屏增加栏数，不放大单个元素** |
| 字号 | 用 `clamp()` 做流体缩放；**绝对下限 16px**（儿童端正文 ≥ 18px） |
| 方向 | 手机锁竖屏体验、字卡与古诗页允许横屏；**不锁屏幕方向**（Web 也锁不住） |
| 形态判定 | **按可用宽度**判定（container query），不按设备型号判定 |

```css
/* styles/responsive.css —— 三档外壳，一份 DOM */
.app-shell {
  display: grid;
  grid-template-areas: "main" "nav";
  grid-template-rows: 1fr auto;
  min-height: 100dvh;
}
@media (hover: hover) { .card:hover { transform: translateY(-2px); } }   /* 仅指针设备 */
@media (min-width: 768px)  { .app-shell { grid-template-areas: "nav main"; grid-template-columns: 88px 1fr; grid-template-rows: 1fr; } }
@media (min-width: 1280px) { .app-shell { grid-template-columns: 240px 1fr; } }
```

#### 2.9.4 大资源加载约定

| 资源 | 规则 |
| --- | --- |
| 本地语音模型（20–60MB） | **绝不进首屏**；首次使用跟读功能时后台下载，进度可见，写入 Cache Storage |
| F0 算法与声调模板（< 100KB） | 内联进主包，**不做懒加载**（核心能力不能延后） |
| 音频素材 | 进单元时预取，LRU 淘汰；**永不进代码包** |
| 中文字体 | 系统字体栈优先；若必须用自定义字体，**必须子集化** |

## 三、后端规范（apps/api）

### 3.1 分层约定

```
routers/    只做参数解析与调用 service，不写业务逻辑
services/   业务逻辑，可被多个 router 复用
models/     Pydantic 模型（请求/响应）
db/         MongoDB 连接、索引初始化、聚合查询
core/       配置、安全、依赖注入、异常处理
tasks/      定时任务与异步任务
```

| 约定 | 规则 |
| --- | --- |
| 路由 | `@router.get("/characters")`，路径不带 `/api/v1` 前缀（由 main 统一挂载） |
| 依赖注入 | 用 `Depends` 注入当前用户、数据库、权限校验 |
| 校验 | 所有入参用 Pydantic 模型，**不接收裸 dict** |
| 响应 | 统一包装为 `{code, message, data}`，用统一 Response 模型 |
| 异常 | 自定义 `BizException(code, message)`，全局 handler 统一转换 |
| 数据库 | 禁止在 router 直接操作集合，必须经 `db/` 层 |

### 3.2 关键实现注意

| 场景 | 注意点 |
| --- | --- |
| 邀请码校验 | **只存哈希**（`SHA-256`）；支持离线 Ed25519 签名码与服务端校验两种模式；限流 + 失败锁定 |
| 口令处理 | 用 **Argon2id**（含盐），禁止 md5/sha1；明文口令不落日志、不入库 |
| 端到端加密同步 | 服务端只存 `cipher_payload`，**不做任何解密**；`revision` 冲突交由客户端合并 |
| 答题写入 | 优先用单文档 `upsert` 设计规避跨文档事务 |
| 复习调度 | SRS 计算为纯函数，便于单测 |
| 批量导入 | 大文件走异步任务，避免请求超时 |
| 语音评测 | 可选增强；调用第三方前先扣配额，失败则回滚；音频用完即删；**无 Key 时整块功能不暴露** |
| 审计日志 | 用装饰器统一记录，防止遗漏 |
| 限流 | 邀请码校验、评测接口必须限流 |
| 落库内容 | 内容优先来自 `content/` 仓库文件；后台写入需可**导出回 JSON**（保证内容可移植） |

> ⛔ **后端红线**：**不实现任何需要企业主体的能力**（实名账号、短信、支付、推送）。这些的路由**不注册**，即使前端被绕过也调不到。

### 3.3 测试要求

| 层次 | 覆盖目标 |
| --- | --- |
| 单元测试 | SRS 算法、拼音比对、题目生成、权限判断 |
| 集成测试 | 关键接口闭环（登录 → 建档案 → 学字 → 报告） |
| 数据校验 | 内容导入的边界情况 |

## 四、接口与数据契约

| 约定 | 规则 |
| --- | --- |
| 命名一致性 | 数据库 `snake_case`，**接口出参也 `snake_case`**，前端在 `api/` 层统一转 camelCase |
| 时间 | 一律 ISO 8601 UTC 字符串 |
| ID | ObjectId 以字符串传输，**不传对象** |
| 枚举 | 前后端共享 `packages/core/constants`，**禁止各写一份**（后端 Pydantic 从同一份 JSON 常量生成） |
| 版本 | 破坏性变更升 `/api/v2`，旧版本至少保留 3 个月 |

### 5.3 代码审查清单

**通用**

- [ ] 有无硬编码的内容数据（字/诗/故事必须来自 `content/` 或接口）
- [ ] 有无硬编码的密钥、域名、手机号
- [ ] 新增接口是否符合 `/api/v1` 约定与统一响应结构
- [ ] 数据表字段变更是否同步更新了数据字典
- [ ] 涉及儿童数据的逻辑是否遵守最小必要原则
- [ ] 是否有对应的单元测试
- [ ] 组件是否超过 300 行

**开源与掩藏专项**：

- [ ] 新增依赖是否**免费且许可兼容**（不引入付费依赖；第三方许可登记到 `THIRD_PARTY_NOTICES.md`）
- [ ] 新增能力是否需要 API Key？若是，是否**可选 + 可降级 + 默认关闭**？
- [ ] 数据访问是否**全部走仓储 / API 客户端**（无 `localStorage` 直连、无自行发请求）
- [ ] 新增/涉及的功能是否用**能力开关**包裹，默认值是否符合 `packages/core/src/flags` 与 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md) 的权威清单
- [ ] 需企业主体的能力是否**四道防线齐全**（见 [2.8.1](#281-能力开关feature-flag)）
- [ ] 是否引入任何**儿童个人身份信息**（姓名/照片/位置/手机号）——若有，直接驳回
- [ ] 新增内容文件是否已在 `content/sources.json` 登记来源与许可（**未登记不得入库**）
- [ ] 是否新增了「按权限跳转外部入口」之类与免费模式冲突的死逻辑

**多端专项检查**（见 [2.9](#29-跨端与多端约定红线)）：

- [ ] `packages/core` 中是否引入了平台 API（`window` / `document` / `localStorage` / `fetch`）
- [ ] 平台差异是否只出现在 `apps/*/src/platform/` 内
- [ ] 新增能力是否在[能力清单](<../02-系统架构/02-多端适配与响应式设计规范.md#72-能力清单的维护>)中登记了三端表现，并提供**降级路径**（而非只隐藏入口）
- [ ] 是否使用了魔法数字断点，而非 `packages/tokens` 的断点常量
- [ ] 新增固定定位/全屏元素是否处理了安全区（`env(safe-area-inset-*)`）与 `100dvh`
- [ ] `hover` 样式是否包在 `@media (hover: hover)` 内
- [ ] 触控热区是否 ≥ 56px（主操作 ≥ 64px）
- [ ] 大体积资源（> 1MB）是否走了按需加载，未进首屏或代码包

## 六、环境与配置

### 6.1 当前需要的变量（✅ 部署 / 开发）

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 后端接口地址。**必填**——内容与学习数据均为服务端存储，缺失则应用无法运行。线上**必须写相对路径** `/api/v1`（同源反代，理由见 [06-2 §一](./02-发布与更新流程.md#一部署拓扑)） | `/api/v1` |
| `VITE_CDN_BASE` | 素材静态地址 | `https://cdn.example.com` |
| `VITE_ENABLE_CONTENT_API` | 是否启用云端内容接口（构建期静态求值） | `false` |
| `VITE_ENABLE_INVITE_AUTH` | 是否启用邀请码身份 | `false` |
| `MONGODB_URI` | 数据库连接（云端后台） | — |
| `JWT_SECRET` | 会话签名密钥（云端后台） | — |
| `INVITE_SIGNING_KEY` | 邀请码签发私钥（**仅后端/离线签发工具**） | — |
| `ADMIN_PASSWORD_HASH` | 单管理员后台口令哈希（Argon2id） | — |
| `ASSESSMENT_API_KEY` | ⚠️ 可选付费语音评测（**不配置即整块功能隐藏**） | — |

### 6.2 ⛔ 掩藏能力的变量（不启用，仅备查）

`SMS_PROVIDER_KEY`、`WECHAT_MP_APPID`、`WECHAT_OPEN_APPID`、`UNIONID_SALT`、`REDIS_URL` —— 这些属于需企业主体的能力（短信/微信/多角色缓存），**当前不配置、不引用**。

**规则**：

- 所有配置走环境变量，**仓库内只提交 `.env.example`**，禁止提交真实密钥。
- **端到端加密的关键点**：同步数据的加密密钥由**用户口令在客户端派生**，服务端**没有任何解密密钥**，因此不存在「数据加密密钥」这类服务端变量——这是设计使然，若有人提出要加，说明方案被改坏了。
- 微信/短信相关密钥（若将来启用）**只允许存在于后端**，AppSecret **绝不下发到前端**。

## 七、开源工程文件（法定义务）

开源仓库根部必须包含以下文件，缺一不可：

| 文件 | 作用 | 要点 |
| --- | --- | --- |
| `LICENSE` | 代码许可 | **MIT**（见 [01-4 4.3](../01-产品规划/04-免费开放与开源策略.md#43-许可证选择)） |
| `LICENSE-CONTENT` | 内容许可 | **CC BY-SA 4.0**（内容与代码双许可，须在 README 顶部显著说明） |
| `README.md` | 面向用户/贡献者 | 与 `docs/`（面向开发者）受众不同；含快速开始、截图、许可声明 |
| `CONTRIBUTING.md` | 贡献指南 | 如何**只改 JSON 贡献一个字条**（最低门槛路径）；PR 规范；内容来源要求 |
| `CODE_OF_CONDUCT.md` | 行为准则 | 面向儿童教育项目，尤其强调内容适龄性 |
| `THIRD_PARTY_NOTICES.md` | 第三方声明 | 依赖与数据的许可全文与署名（`pinyin-data` / `hanzi-writer-data` / `chinese-poetry` 等） |
| `.gitignore` | 忽略 | **必须含 `.env`、`node_modules/`、`dist/`、本机绝对路径产物** |
| `.github/workflows/*` | CI | 类型检查 + lint + 内容 Schema 校验 + **密钥扫描** + 构建 + 部署 |

**开源前置检查（第一次公开推送前必做）**：

1. **密钥清洁**：全历史扫描（`gitleaks` / `trufflehog`），`.env` 从未入库。
2. **依赖许可扫描**：产出 `THIRD_PARTY_NOTICES.md`；剔除与 MIT 不兼容的依赖。
3. **内容来源溯源**：每个数据文件标注来源与许可；**来源不明的数据一律先删除再重建**。
4. **个人信息清洁**：清除提交历史中的真实姓名、手机号、邮箱、**本机绝对路径、内网 IP**。

> ⛔ **一次性数据生成脚本不得进入公开仓库**——常含本机绝对路径并暴露数据生成方式；发布前统一清理。
