# 03-2 数据字典

> **单一事实来源**：字段定义只在本文件维护，其他文档引用本文件而非复制。
> 集合结构设计见 [03-1 MongoDB 集合设计](./01-MongoDB集合设计.md)。

---

## 一、通用约定

| 约定 | 规则 |
| --- | --- |
| 集合命名 | 小写 `snake_case`，复数形式（`characters`） |
| 字段命名 | 小写 `snake_case`（`stroke_count`），前端转 camelCase |
| 主键 | MongoDB `ObjectId`，对外暴露为字符串 |
| 时间 | 一律 UTC `ISODate`，前端按用户时区展示 |
| 日期（无时间） | 字符串 `YYYY-MM-DD`（如 `daily_tasks.date`） |
| 金额 | **整数，单位「分」**（`19800` = 198 元），避免浮点误差 |
| 布尔 | 真 `true` / 假 `false`，**不用 0/1** |
| 空值 | 明确用 `null` 而非省略字段（便于索引与校验） |
| 素材引用 | 存 `assets._id`，字段名以 `_ref` 结尾，**不存 URL** |
| 状态字段 | 统一 `status`，取值见第五章 |
| 软删除 | 用 `status: 'deleted'`，不物理删除业务数据 |

## 二、字段类型速查

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| `ObjectId` | 文档主键或外键 | `ObjectId("...")` |

## 三、用户域与身份域

> 默认形态是**纯本地**：孩子学习数据（`learning_records` / `char_review_states` / `children` 等）主存储在 IndexedDB，本域集合仅描述「开启云端同步后，服务端长什么样」。身份采用**邀请码 + 自设口令**，不需要企业主体（无手机号、无微信、无实名）。

| 集合 | 形态 | 主存储位置 | 说明 |
| --- | --- | --- | --- |
| `accounts` | ✅ 当前 | 前端 / 轻后端 | 邀请码身份主体 |
| `invites` | ✅ 当前 | 前端（离线签名）/ 轻后端 | 邀请码 |
| `recovery_codes` | ✅ 当前 | 前端 / 轻后端 | 恢复码 |
| `children` | ⏸️ 可选 | **前端 IndexedDB（主）** | 儿童档案，云端仅镜像 |
| `guardian_consents` | ⛔ 掩藏 | — | 配合实名账号，不启用 |

> `devices` / `sync_objects` / `stats_events` / `feedbacks` / `audit_logs` 见第七章；`users` / `otp_codes` 为掩藏集合，处置见 [§3.5](#35-掩藏集合仅兼容保留当前不启用)。

### 3.1 `accounts` — 邀请码身份主体 ✅

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `_id` | ObjectId | ✅ | ✅ | 主键 |

| `avatar_key` | string | ✅ | — | 预设头像标识，**不存真实照片** |

| `invite_code_hash` | string \| null | ✅ | — | 首次激活所用邀请码的哈希（**不存明文码**） |
| `sync_key_salt` | string \| null | ✅ | — | 端到端加密密钥派生盐（客户端派生，服务端不可解） |
| `e2e_enabled` | bool | ✅ | — | 是否启用端到端加密同步 |
| `role` | string | ✅ | — | `learner`（默认）/ `admin` |
| `status` | string | ✅ | — | `active` / `disabled` / `deleted` |
| `access_tier` | string | ✅ | — | `invite_only` / `open`，对应准入策略 |
| `last_login_at` | date \| null | ✅ | — | 最后登录时间 |
| `failed_attempts` | int | ✅ | — | 连续口令错误次数（达阈值触发锁定） |
| `locked_until` | date \| null | ✅ | — | 锁定截止时间，`null` = 未锁定 |
| `created_at` | date | ✅ | — | 创建时间 |
| `updated_at` | date | ✅ | — | 更新时间 |

> ⚠️ **无手机号、无邮箱、无微信字段**。这是刻意的：任何一项都会把项目拖回「需要企业主体 + 实名合规」的轨道。
> 身份关系：一个 `accounts` 可对应 1–N 个 `children`（多孩子共用一台设备）。

### 3.2 `invites` — 邀请码 ✅

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `_id` | ObjectId | ✅ | ✅ | 主键 |
| `code_hash` | string | ✅ | ✅ | 邀请码哈希（**只存哈希**）；明文码仅出现在签发时 |
| `code_hint` | string | ✅ | — | 展示用掩码（如 `HANZI-4K9F-****`），**不含完整码** |
| `batch_id` | string | ✅ | — | 批次标识，便于整批作废 |
| `channel` | string | ✅ | — | 发放渠道：`self` / `friend` / `community` / `test` |
| `max_uses` | int | ✅ | — | **可激活次数，恒为 1**。邀请码即账号的登录标识，`accounts.invite_code_hash` 上有唯一索引（见 [03-1 §3.1](./01-MongoDB集合设计.md)），一个码只能激活一个账号。字段保留是为了「字段只增不改不删」，**后台不再开放设置**（请求模型已限 `le=1`） |
| `used_count` | int | ✅ | — | 已激活次数（0 或 1） |
| `bound_account_ids` | ObjectId[] | ✅ | — | 已用此码激活的 `accounts`（一码一账号 → 至多 1 个） |
| `expires_at` | date \| null | ✅ | — | 过期时间，`null` 表示不过期 |
| `revoked_at` | date \| null | ✅ | — | 作废时间 |
| `note` | string \| null | ✅ | — | 备注（发放对象，**不写儿童信息**） |
| `created_by` | ObjectId \| null | ✅ | — | 签发人；`null` = 离线签名批次 |
| `created_at` | date | ✅ | — | 创建时间 |

**`code_hash` 规则**：`SHA-256(code)`，`code` 为 12 字符 Crockford Base32（60-bit 熵）。校验两种模式：**离线 Ed25519 签名**（纯前端，无需服务器）或**服务端查询**（可撤销）。
