## 三、身份与学习主体域

> 本域集合承载「邀请码 + 自设密码」的身份、家庭档案与设备会话。**字段定义见 [03-2 数据字典](./02-数据字典.md) 第三章**，本节只列用途与索引。

### 3.1 `accounts` — 邀请码身份主体（✅ 当前）

**职责**：承载「邀请码 + 自设密码」注册登入的匿名账号，**服务端不存任何身份信息**（无手机号、邮箱、真实姓名、微信 ID）。一个账号可对应 1–N 个 `children`。

**字段**：见 03-2 §3.1。

**索引**

| 索引                            | 类型     | 用途               |
| ----------------------------- | ------ | ---------------- |
| `invite_code_hash`            | unique | 「一码一账号」约束 + 登录查询 |
| `{status: 1, created_at: -1}` | 复合     | 后台筛选             |

> `invite_code_hash` 唯一索引即「一码一账号」；若要支持家庭共享码，改为普通索引（设计取舍见 [02-5 §3.4](../02-系统架构/05-邀请码身份与准入体系.md)）。

### 3.2 `invites` — 邀请码（✅ 当前）

**职责**：邀请码的发放、用量与吊销；**只存哈希**，完整码只在签发时返回一次。

**字段**：见 03-2 §3.2。

**索引**

| 索引                             | 类型        | 用途    |
| ------------------------------ | --------- | ----- |
| `code_hash`                    | unique    | 校验查询  |
| `{batch_id: 1, revoked_at: 1}` | 复合        | 按批次吊销 |
| `expires_at`                   | 普通（可 TTL） | 过期清理  |

> **离线签名码不入库**：Ed25519 签名码是「无状态」的，由持有私钥者签发、客户端本地验签，服务端不需要知道任何码。

### 3.3 `recovery_codes` — 恢复码（✅ 当前）

**职责**：忘记密码且无手机号找回时的唯一自救通道；**只存哈希**，一次使用后失效。

**字段**：见 03-2 §3.3。

**索引**：`{account_id: 1}`（unique）、`{code_hash: 1}`

### 3.4 `children` — 儿童档案（✅ 当前）

**职责**：儿童档案（学习主体），**以服务端 MongoDB 为唯一真源**；儿童不单独注册账号，挂在 `accounts` 下。

**字段**：见 03-2 §3.4。

**索引**：`{account_id: 1}`（普通）、`{account_id: 1, status: 1}`

## 四、内容域（✅ 当前）

> 本域字段与 `content/` 目录的内容包 JSON **完全一致**，可原样导入导出。

### 4.1 `characters` — 汉字主表

**职责**：**全系统最重要的集合**，汉字主表（核心资产）。

**字段**：见 03-2 §4.1。

**索引**

| 索引                           | 类型     | 用途          |
| ---------------------------- | ------ | ----------- |
| `char`                       | unique | 唯一性约束       |
| `{grade: 1, difficulty: 1}`  | 复合     | 出题选题        |
| `{level: 1, status: 1}`      | 复合     | 分级学习        |
| `tags`                       | 多键     | 主题筛选        |
| `unit_refs.unit_id`          | 多键     | 按**自编单元**查询 |
| `char` + `meaning` + `words` | 文本索引   | 后台搜索        |
| `status`                     | 普通     | 后台列表        |

### 4.2 `poems` — 古诗

**职责**：古诗。原文取自开源数据集 [`chinese-poetry`](https://github.com/chinese-poetry/chinese-poetry)（MIT，原文公版）；注音、释义、赏析为自编内容。

**字段**：见 03-2 §4.2。

**索引**：`title`（普通）、`{grade: 1, difficulty: 1}`、`theme_tags`（多键）、`source`、`key_characters`（多键）

### 4.3 `curriculum_units` — 自编单元

**职责**：按主题、字频、难度自主编排的单元，**非出版社映射**。

**字段**：见 03-2 §4.3。

**索引**：`{unit_code: 1}`（unique）、`{grade_num: 1, semester: 1, order: 1}`

> **红线**：不复现任何出版物的单元顺序、课文标题与插图；`organize_by` 记录编排依据。用户若需「跟课本学」，用**自定义单元**由家长自行勾选（见 [01-2 3.3](../01-产品规划/02-产品定位与内容体系设计.md)）。

### 4.4 `lessons` — 关卡

**职责**：关卡（课程编排）。

**字段**：见 03-2 §4.4。

**索引**：`{level: 1, order: 1}`、`unit_id`

### 4.5 `assets` — 素材

**职责**：音频/图片/笔顺等素材。`copyright` **必填**——面向儿童的商用内容，版权链必须可追溯；`*_ref` 字段指向本集合而**不存 URL**，素材替换、CDN 迁移时无需批量更新内容表。

**字段**：见 03-2 §4.5。

**索引**：`{type: 1, subtype: 1}`、`storage_key`（unique）、`status`

### 4.6 `stories` — 故事与儿歌

**职责**：故事与儿歌。

**字段**：见 03-2 §4.6。

**索引**：`{level: 1, grade: 1}`、`status`

## 五、学习域（✅ 当前）

> ⚠️ **本域集合以服务端为唯一真源**：学习记录、答题明细、复习状态、错题与每日任务全部存服务端 MongoDB（见 [02-3 存储与后端策略](../02-系统架构/03-存储与后端策略.md)）；可选的云端家庭档案以端到端加密形式存放于 `sync_objects`。**字段定义见 [03-2 数据字典](./02-数据字典.md) 第五章**。

### 5.1 `learning_records` — 学习行为流水

**职责**：追加型数据，**永不更新**。离线队列上报时用 `occurred_at`（客户端时间）排序，`created_at` 记录入库时间以便排查。

**字段**：见 03-2 §5.1。

**索引**：`{child_id: 1, occurred_at: -1}`、`{child_id: 1, event_type: 1, occurred_at: -1}`、`{client: 1, occurred_at: -1}`

> `client` / `platform` / `device_form` 三件套用于：① 判断多端投入回报；② 定位「只在某端出现」的缺陷；③ 观测降级路径的触发率。取值与判定规则见 [02-2 §7.1](../02-系统架构/02-多端适配与响应式设计规范.md#71-运行时能力探测关键实现)。

### 5.2 `answer_records` — 答题明细

**职责**：答题明细。`char` 为**有意的反范式**（报表与错题本高频展示汉字本身）；量级会到亿级，需按月分表或 TTL 归档。

**字段**：见 03-2 §5.2。

**索引**：`{child_id: 1, character_id: 1, occurred_at: -1}`、`{child_id: 1, is_correct: 1, occurred_at: -1}`

### 5.3 `char_review_states` — 复习状态（SRS 核心）

**职责**：每个字的复习状态。

**字段**：见 03-2 §5.3。

**索引**：`{child_id: 1, next_review_at: 1}`（**最关键索引**）、`{child_id: 1, character_id: 1}`（unique）

> 每日任务的核心查询是 `find({child_id, next_review_at: {$lte: today}})`，因此复合索引顺序必须 `child_id` 在前。

### 5.4 `wrong_questions` — 错题本

**职责**：错题本；同一字多次答错只保留一条并累加计数（需 `upsert` 写入）。

**字段**：见 03-2 §5.4。

**索引**：`{child_id: 1, resolved: 1, last_wrong_at: -1}`

### 5.5 `daily_tasks` — 每日任务

**职责**：每日任务；在用户当天首次进入时**懒生成**（避免零点批量跑全量用户），已生成则直接返回。

**字段**：见 03-2 §5.5。

**索引**：`{child_id: 1, date: 1}`（unique）

## 七、系统与同步域

### 7.1 `audit_logs` — 操作审计（✅ 当前）

**职责**：邀请码生成/吊销、账号禁用/删除、内容变更（自托管后台内）的审计留痕。

**字段**：见 03-2 §7.1。

**索引**：`{created_at: -1}`、`{action: 1, created_at: -1}`、`{target_collection: 1, target_id: 1}`

**设计说明**

- **隐私边界**：⚠️ **绝不记录明文邀请码、明文密码、密文载荷内容**。`diff` 只记元数据字段的变化。
- **与 Git 的分工**：内容变更的主路径（PR）由 Git 提交历史留痕，无需重复记录；此处只记后台内的操作。

### 7.2 `devices` — 设备与会话（✅ 当前）

**职责**：登记多端/多设备，支撑登录吊销与分端分析。推送相关字段（`push_token` / `subscribed_topics` 等）属 **⛔ 掩藏**（需推送服务，属企业主体能力），当前不启用。

**字段**：见 03-2 §7.3。

**索引**：`{account_id: 1, client_id: 1}`（unique + sparse，**会话归属键**）、`{account_id: 1, client: 1}`、`{refresh_token_hash: 1}`、`{last_active_at: -1}`；`push_token`（unique + sparse，⛔ 掩藏）

> 一个账号多条记录（多端 + 多设备），不是一条。  
> ⚠️ **`client_id` 是客户端持久化的设备随机 id**（web 端 `localStorage['sc.deviceId']`），  
> 不是用户标识。它必须参与唯一键 —— 否则同形态的两台设备会被 upsert 到同一条记录上，  
> 后登录者覆盖先登录者的 `refresh_token_hash`，先登录的设备在 Access Token 过期后  
> **刷不回会话**，表现就是「一台登录、另一台被踢下线」。  
> `sparse` 是为了跳过早期版本留下的、没有该字段的旧记录。  
> 索引缺省时（客户端未上报）退化为按 `client` 区分，多设备语义失效但不会报错。

### 7.3 `sync_objects` — 云端档案密文块（✅ 已实现 · 默认关闭）

**职责**：端到端加密同步对象。

**字段**：见 03-2 §7.4。

**索引**：`{account_id: 1, object_type: 1, object_key: 1}`（unique）、`{updated_at: -1}`

**设计说明**

- ⚠️ **服务端只存密文**：密钥由用户密码经 Argon2id 派生，**服务端无论如何都解不开**；即使数据库泄漏，也拿不到儿童学习数据（见 [02-5 §4.5](../02-系统架构/05-邀请码身份与准入体系.md)）。
- 按 `object_type` 分块而非整档上传：便于增量同步与冲突处理。
- **同步冲突策略**：追加型数据（学习记录）按 `occurred_at` 去重合并；状态型数据（复习状态）取 `revision` 更大者。

### 7.4 `stats_events` — 匿名统计（✅ 当前）

**职责**：小时桶聚合的匿名统计。

**字段**：见 03-2 §7.5。

**索引**：`{bucket_date: 1, event_name: 1}`、`{content_ref: 1}`

**设计说明**：⚠️ **只存聚合计数，不含任何账号或设备标识**（无 `account_id` 字段）；聚合计数上报后服务端 `$inc` 累加即可（见 [02-3 第八章](../02-系统架构/03-存储与后端策略.md)）。

### 7.5 `feedbacks` — 反馈与内容纠错（✅ 当前）

**职责**：用户反馈与内容纠错，是少数「能知道用户遇到什么」的渠道。

**字段**：见 03-2 §7.6。

**索引**：`{status: 1, created_at: -1}`、`{category: 1}`

## 八、掩藏集合（需企业主体，不启用）

以下集合**只保留契约与类型**，不启用、不打包、不部署；将来具备企业主体时是「打开开关 + 换一次注入」，而非重写。

| 集合                   | 用途               | 开关名                 | 状态          |
| -------------------- | ---------------- | ------------------- | ----------- |
| `users`              | 实名家长账号（手机号 / 微信） | `enableAccountAuth` | ⛔ 需企业主体，不启用 |
| `guardian_consents`  | 监护人同意留痕          | `enableAccountAuth` | ⛔ 需企业主体，不启用 |
| `otp_codes`          | 短信验证码            | `enableAccountAuth` | ⛔ 需企业主体，不启用 |
| `orders`             | 支付订单             | `enablePayment`     | ⛔ 需企业主体，不启用 |
| `subscriptions`      | 订阅权益             | `enablePayment`     | ⛔ 需企业主体，不启用 |
| `push_subscriptions` | 推送订阅（原生端）        | `enableNativeApp`   | ⛔ 需企业主体，不启用 |

## 九、分片与容量规划

| 集合                   | 增长率预估                            | 策略                              |
| -------------------- | -------------------------------- | ------------------------------- |
| `answer_records`     | 每活跃用户每天约 50 条 → 10 万用户 = 500 万/天 | 按月归档；分片键 `{child_id: "hashed"}` |
| `learning_records`   | 每活跃用户每天约 3 条                     | 保留 1 年，超期归档                     |
| `char_review_states` | 每用户约 3000 条上限                    | 无需分片，靠索引即可                      |
| `characters`         | 3000 条，几乎不变                      | 全量常驻内存缓存                        |


| `sync_objects` | 每账号 10–50 个密文块，随版本累积 | 保留最近 N 个版本，旧版本定期清理 |  
| `stats_events` | 小时桶聚合，量很小（亿级明细已被聚合掉） | 无需分片；超 180 天归档 |  
| `invites` | 千级 | 无需分片；过期批次可归档 |  
| `devices` | 每账号 1–3 条 | 无需分片；沉默设备（> 180 天无活动）定期清理 |

> **注意**：学习域数据全部落在服务端，容量随活跃用户线性增长；分片与归档策略按下表执行。

---

**归档策略**：`answer_records` 明细保留 6 个月用于学情分析，之后聚合为日统计并删除明细。
