# 02-3 存储与后端策略

> 本文档回答一个问题：**数据存在哪里、后端承担什么职责、浏览器端还保留什么？**
>
> 结论：**服务端为唯一真源 + 内容即仓库 + 单机自托管后端**。学习数据、儿童档案、进度与内容全部存服务端
> MongoDB；浏览器只保留凭据与少量 UI 偏好；内容以仓库内 JSON 维护、导入数据库后经接口下发。
>
> 配套：身份与准入见 [02-5 邀请码身份与准入体系](./05-邀请码身份与准入体系.md)；数据模型见 [03-1 集合设计](../03-数据设计/01-MongoDB集合设计.md)；未来演进见 [02-4 架构演进与优化方向](./04-架构演进与优化方向.md)。

---

## 一、总体存储策略：服务端为唯一真源

系统采用**服务端权威（Server-Authoritative）**的数据模型：**所有业务数据以 MongoDB 为准，浏览器不做业务数据的持有方。**

```
┌────────────────────────────────────────────────────────────────────┐
│                        浏览器 / PWA（apps/web）                      │
│  只保留四类本地键（均不含学习数据）：                                 │
│    sc.session        会话凭据（JWT）                                 │
│    sc.deviceId       设备标识（区分同账号多设备会话）                 │
│    sc.currentChild   当前选中的孩子（纯 UI 偏好，丢了重选即可）        │
│    sc.loginMemory    「记住账号与密码」勾选后才写，仅本机             │
└───────────────────────────────┬────────────────────────────────────┘
                                │ HTTPS：/api/v1/*（同源反代）
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│                   云端后台（apps/api，FastAPI + MongoDB）            │
│  业务数据：账号 / 档案 / 学习记录 / 复习状态 / 错题 / 徽章 / 同步对象  │
│  内容数据：字库 / 古诗 / 单元 / 关卡 / 故事 / 短文 / 徽章定义          │
│  素材：图片 / 音频 / 笔顺（文件落盘 + assets 元数据入 MongoDB）        │
│  统计：匿名聚合事件（禁止个人标识）                                   │
└────────────────────────────────────────────────────────────────────┘
```

### 1.1 为什么以服务端为准

| 动机 | 说明 |
| --- | --- |
| **跨设备一致** | 同一账号在手机 / iPad / 桌面看到同一份进度，不再依赖「导出文件再导入」 |
| **多档案与家庭共用** | 儿童档案、多孩切换、家长查看天然由服务端承载 |
| **学情报告可信** | 报告在服务端基于全量记录聚合，口径统一、可复算 |
| **内容集中管理** | 内容改一处即对全体用户生效，不必等客户端发版 |
| **复习调度可演进** | 调度计算、批量结算放在服务端，避免各端算法漂移 |

> **代价与应对**：以服务端为准意味着「必须能连上后端」。对应措施是**把后端做到极简、单机可维护**（见第五章），并保留**导出 / 导入**作为不依赖任何服务的备份手段（见第七章）。

### 1.2 存储分层

| 层 | 载体 | 存什么 | 说明 |
| --- | --- | --- | --- |
| 业务数据 | **MongoDB** | 账号、设备、儿童档案、学习记录、答题记录、复习状态、错题、每日任务、徽章、同步对象 | 唯一真源；无 Redis、无外部缓存 |
| 内容数据 | **MongoDB** | 字库、古诗、单元、关卡、故事、短文、徽章定义、内容清单 | 由 `content/` JSON 导入，详见第三章 |
| 素材文件 | **磁盘 / 命名卷 + `assets` 集合** | 图片、音频、笔顺 JSON | 文件落 `ASSET_DIR`，元数据入 MongoDB；内容文档只存 `*_ref`，出参展开为 `*_url` |
| 匿名统计 | **MongoDB** | 功能使用计数、完成度、错误分布（聚合，无个人标识） | 模型层禁止 `account_id` / `child_id` / `client_id` |
| 浏览器 | **localStorage（仅四类键）** | 会话凭据、设备标识、UI 偏好、登录记忆 | 不含任何学习数据；见第二章 |

## 二、浏览器端只保留什么

前端**不持有业务数据**，localStorage 只允许承载四类键：

| 键 | 用途 | 为什么必须留在本地 |
| --- | --- | --- |
| `sc.session` | 会话凭据（JWT） | 路由守卫在首个 tick 就要判断登录态，必须**同步可读**；异步存储会导致「进页面闪一下登录页再跳回」 |
| `sc.deviceId` | 设备标识 | 服务端按 `client_id` 为每个登录会话建 `devices` 记录；缺它时同形态设备会被认成同一台，后登录方覆盖先登录方的 Refresh Token（表现为「iPad 一登，手机被顶下线」） |
| `sc.currentChild` | 当前选中的孩子 | 纯 UI 偏好，丢了最多重选一次 |
| `sc.loginMemory` | 记住的账号与密码 | 用户显式勾选「记住」才写，仅本机、不上传；公共设备有明确提示 |

**纪律**：任何「以本地为主存储」的新键都属于违规。数据访问一律走 `packages/core` 的数据仓储与 API 客户端，组件内不得直接读写存储。

## 三、内容即仓库（Content-as-Repo）

内容与代码**物理分离**：内容以仓库内 JSON 维护，贡献者**只需改 JSON**，不必懂前端。

### 3.1 内容包结构

```
content/                          # ⭐ 内容与代码分离，Git 版本化
├── manifest.json                 # 内容包清单：版本、各文件哈希、条目数
├── characters/grade-1.json       # 字库（按年级分文件）
├── poems/required-75.json        # 古诗
├── lessons/units.json            # 单元编排
├── lessons/lessons.json          # 关卡编排
├── stories/stories.json          # 识字短文（短文与儿歌）
├── badges/badges.json            # 徽章定义
├── schema/*.schema.json          # JSON Schema（CI 校验 + 后台表单共用）
└── sources.json                  # ⭐ 数据来源与许可清单
```

**字段规格三处同源**：内容 JSON、MongoDB 集合、前端 TS 类型由同一份字段定义派生（单一事实来源在 [03-2 数据字典](../03-数据设计/02-数据字典.md)）。因此内容文件可**原样导入** MongoDB，无需转换；后台表单也可由同一份 JSON Schema 驱动。

### 3.2 内容分发链路

```
content/*.json ──导入──► MongoDB（内容集合）──接口──► 前端
     │              ▲                                  │
     │              └── scripts/seed 或 管理后台导入     │
   Git 版本化 / PR 评审 / CI 校验                  GET /content/bootstrap（一次拉全量）
```

| 环节 | 实现 | 说明 |
| --- | --- | --- |
| 维护 | Git（仓库内 JSON） | 版本、评审、回滚、审计由 Git 天然承担；管理后台是其**可视化补充** |
| 校验 | `scripts/content/validate.mjs` + JSON Schema | CI 校验字段、拼音一致性、重复条目等 |
| 导入 | `scripts/seed`（按表拆分的种子文件）或后台 `/admin/content/import` | upsert 幂等；白名单集合支持清理过期条目 |
| 下发 | `GET /content/bootstrap` | 登录后一次拉取全量内容（manifest + 字库 + 古诗 + 单元 + 关卡 + 故事 + 短文 + 徽章） |
| 增量读取 | `GET /content/{collection}` 及子资源接口 | 按需读取单个字 / 诗 / 单元 / 关卡 |

### 3.3 内容版本

| 字段 | 说明 |
| --- | --- |
| `content_version` | 内容包语义化版本，如 `1.1.0` |
| `min_app_version` | 使用此内容包所需的最低应用版本 |
| `checksum` | 各内容文件的 SHA-256 哈希，用于比对 |
| `updated_at` | 内容更新时间 |
| `counts` | 各内容类型的条目数 |

> **兼容性硬约束**：内容包必须带 `min_app_version`。若内容要求的应用版本高于当前客户端，客户端**忽略不认识的字段**，避免「字段不认识 → 渲染崩溃」。

## 四、后端职责分层

### 4.1 三类事情分开

| 类型 | 能力 | 处理 |
| --- | --- | --- |
| **可以做**（只需服务器） | 内容读取接口、**邀请码校验与身份**、匿名统计、云端家庭档案与加密同步、反馈收集、素材托管、**单管理员内容后台** | ✅ 已实现并部署 |
| **必须掩藏**（需企业主体） | 手机号 / 微信账号、支付与订阅、推送、微信小程序、iOS/Android App | ⛔ 写契约与开关，不注册路由、不打包、不可达 |
| **本期不做**（设计取舍，**不需要企业主体**） | 多角色 RBAC 后台 | ⛔ 单管理员足够，不做（多角色属过度设计） |
| **交给本地**（无业务数据） | 会话凭据、设备标识、UI 偏好 | ⭐ 浏览器 localStorage 四类键 |

> **关键区分**：**「不做需要企业主体的事」不等于「不能有服务器」**。邀请码身份、内容后台、匿名统计、跨设备同步**只需服务器**，属于已实现范围；只有手机号/微信账号、支付、小程序、App 才进入掩藏层。**多角色 RBAC 不属于企业主体约束**，它是「单人维护下不做」的范围决定——写进掩藏层只是因为同样「写契约、不启用」。

### 4.2 后端模块

| 模块 | 职责 | 为什么由后端承担 |
| --- | --- | --- |
| **内容读取** | 按清单 / 单元 / 年级下发内容，支持单条与批量 | 内容与代码分离，改内容不必发版 |
| **邀请码校验与身份** | 校验邀请码、注册、登入、恢复码重置 | 需要「撤销邀请码」「设备会话管理」时必然在服务端 |
| **儿童档案** | 多档案增删改查、档案统计 | 跨设备共享的前提 |
| **学习与复习** | 答题上报、批量结算、复习到期、错题、进度 | **服务端算，客户端不算**，保证口径统一 |
| **学情报告** | 掌握率、趋势、薄弱字、周报服务端聚合 | 基于全量记录，结果可复算 |
| **匿名统计** | 功能使用计数、完成度、错误分布 | 无账号也能知道「哪里卡住了」；只上报聚合计数 |
| **云端家庭档案（可选）** | 邀请码家庭档案 + 端到端加密的跨设备同步 | 缓解「换设备丢进度」，不需要企业主体 |
| **反馈收集** | 用户提交问题与内容纠错 | 替代第三方工单系统 |
| **素材托管** | 图片 / 音频 / 笔顺文件与元数据 | 内容文档只存引用，换素材不碰内容 |
| **单管理员后台** | 内容 CRUD、批量导入导出、邀请码管理、用户查看、配置 | 可视化编辑比手写 JSON 高效 |

### 4.3 轻量化纪律

| 纪律 | 原因 |
| --- | --- |
| **单机 Docker Compose，不用 K8s、不用微服务** | 运维成本要低到「一个人能维护」 |
| **不引入 Redis**（内容量小，全量加载；会话用 JWT + `devices` 吊销） | 少一个组件少一份故障 |
| **不引入消息队列**，统计异步写用后台任务 | 同上 |
| **最小权限：后台不做 RBAC，只做单管理员鉴权** | 维护者一人，多角色是过度设计 |
| **一键部署脚本 + 环境变量模板，密钥只走环境变量** | `docker compose up` 即可跑起；密钥不进仓库 |

## 五、鉴权与会话

| 项 | 设计 |
| --- | --- |
| 学习者身份 | **邀请码 + 自设密码**（用户名 / 密码至少填一） |
| 密码存储 | **Argon2id**（含盐），明文不落日志、不入库 |
| 邀请码 / 恢复码 / Refresh | 只存 **SHA-256 哈希**；邀请码 12 位 Crockford Base32（60 bit 熵），失败信息统一以防枚举 |
| 会话 | 短期 Access（JWT）+ 可吊销 Refresh（只存哈希）；按 `client_id` 区分设备，多设备可同时在线 |
| 防暴力 | 失败 5 次锁定 15 分钟；按 `client_id` + IP 限流 |
| 管理员 | 密码（Argon2id）换管理员 JWT，或 `X-Admin-Password` 头；**服务端二次校验**，前端隐藏不作为权限控制 |

> 完整的威胁模型、准入放量策略与端到端加密设计见 [02-5 邀请码身份与准入体系](./05-邀请码身份与准入体系.md)。

## 六、掩藏层：写代码但不启用

需要企业主体的能力**不做，但不能不做设计**——契约、类型、开关、目录骨架全部写好，代码存在但**默认关闭、不打包、不可达**。

| 能力 | 开关名 | 默认 | 状态 |
| --- | --- | --- | --- |
| 手机号 / 微信账号 | `enableAccountAuth` | 关 | ⛔ 需企业主体，契约保留 |
| 支付与订阅 | `enablePayment` | 关 | ⛔ 需企业主体，集合与契约保留 |
| 微信小程序 | `enableMiniprogram` | 关 | ⛔ 需企业主体 |
| iOS / Android App | `enableNativeApp` | 关 | ⛔ 需企业主体 |

**掩藏的准确含义**：四道防线同时成立——① 路由不注册（关闭时该路由**不存在**）；② 组件不渲染；③ 调用即抛 `FeatureDisabledError`；④ 类型与契约**始终保留**。掩藏能力开关**禁止被运行期远端配置打开**（见 `packages/core/src/flags`）。

> 一句话：**掩藏 = 不可打包 + 不可达 + 不可调，而不是看不见。** 用 `display:none` 隐藏按钮不算掩藏。

## 七、数据可迁移性与备份

| 层次 | 机制 | 依赖 | 用途 |
| --- | --- | --- | --- |
| **① 导出 / 导入文件** | 导出 `.json`（含 `schema_version`），可导入还原 | ❌ 无 | **备份与迁移的底线**，不依赖任何服务 |
| **② 恢复码** | 注册时一次性返回，忘记密码时重置 | 服务端 | 见 [02-5](./05-邀请码身份与准入体系.md) |
| **③ 云端家庭档案** | 邀请码家庭档案（`enableCloudProfile`）+ 端到端加密（`enableE2EEncryption`）：服务端只存密文 | 服务端 | 多端用同一码与密码访问，默认关闭、默认加密 |

> **核心原则**：数据主存于服务端，**导出 / 导入是备份手段，不是唯一通路**；端到端加密的云档案默认关闭、密钥由用户密码在客户端派生，**服务端没有解密密钥**。

## 八、匿名统计与隐私边界

统计的目的是「知道哪里卡住了」，不是「知道谁在用」。

| 允许 | 禁止 |
| --- | --- |
| 功能使用次数、页面停留时长（聚合） | 任何个人身份信息（姓名、手机号、微信 ID） |
| 内容完成度、错题分布（按内容维度） | 儿童真实姓名、照片、精确位置 |
| 错误堆栈、设备类型与浏览器版本 | 录音原始数据、可识别个体的行为轨迹 |
| 匿名设备标识（随机生成，不与身份关联） | 将匿名数据与任何第三方数据源关联 |

> 统计接口 `POST /stats/events` 由模型层强制：`stats_events` 集合**禁止** `account_id` / `child_id` / `client_id` 字段。

## 九、部署与配置

| 项 | 设计 |
| --- | --- |
| 编排 | `deploy/` 下四份**独立** compose：`mongo` / `api` / `web` / `admin`，互不牵连 |
| 网络 | 均 `network_mode: host`，容器直接占用宿主端口，不做端口映射 |
| 前端托管 | `web` 容器用 nginx 托管构建产物，并把 `/api/` **同源反代**到 `127.0.0.1:8000`——一次解决混合内容拦截与跨源白名单 |
| 配置 | 密钥只走环境变量（见根 `.env.example`）；`JWT_SECRET`、`ADMIN_PASSWORD_HASH` 等部署必须替换 |
| 运维脚本 | `scripts/` 按用途与服务分目录：`db` / `api` / `web` / `admin` / `content` / `seed` / `dev` / `lib` |
| 备份 | 每日 dump（内容 + 身份 + 统计），见 `scripts/db/backup.sh` |

> ⚠️ **含 `$` 的环境变量值（Argon2 哈希、base64 密钥）必须用单引号包住**：Docker Compose 用 dotenv 解析，未加引号会把 `$xxx` 当变量引用替换成空串。
>
> 完整的部署与更新流程见 [06-2 发布与更新流程](../06-工程规范/02-发布与更新流程.md)。
