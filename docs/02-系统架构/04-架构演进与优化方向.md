# 02-4 架构演进与优化方向

> 本文档记录**在当前系统之上可以怎么继续优化**：哪些是近期该补齐的短板，哪些是规模化后才需要做的事，
> 哪些是需要外部前提（企业主体）才能激活的能力。
>
> 定位：**这是一份方向清单，不是排期承诺**。每条都给出「现状 → 优化点 → 触发条件」，便于按需取用。
> 当前整体设计见 [02-1 系统总体架构与技术选型](./01-系统总体架构与技术选型.md) 与 [02-3 存储与后端策略](./03-存储与后端策略.md)。

---

## 一、演进原则

| 原则 | 含义 |
| --- | --- |
| **够用即止** | 单人可维护是硬约束。不为「可能的规模」提前引入 Redis、消息队列、微服务、K8s |
| **契约先行** | 一切改动的兼容性由 TS 类型契约 + 接口版本（`/api/v1`）保证，破坏性变更升 `/api/v2` |
| **内容与代码分离** | 内容规模化靠「改 JSON + 导入」，不靠发版；优化内容生产链路优先于优化运行时 |
| **可降级** | 付费 / 外部服务相关能力必须可选、可降级、默认关闭，不破坏「clone 即跑」 |
| **先补齐闭环，再谈规模** | 当前最大短板是**内容量**，而非架构承载力 |

## 二、近期优化：补齐现有闭环

### 2.1 内容规模化（当前最大短板）

现状：内容清单仅 **字库 83 条 / 古诗 3 首 / 单元 7 / 关卡 14 / 故事 5 / 短文 6 / 徽章 7**，远未达到可用规模。

| 优化点 | 说明 |
| --- | --- |
| 字库扩至 1600 字（一、二年级）→ 3000 字 | 基础属性（拼音 / 笔画 / 笔顺）可用白名单数据源脚本批量生成；释义 / 组词 / 例句走人工或社区众包 |
| 古诗扩至课标必背 75 首 → 150 首 | 原文取自公共领域开源数据集（`chinese-poetry`），需自编注音、短释义、赏析 |
| 短文与故事滚动扩充 | 短文按「已学字覆盖率 ≥ 75%」筛选，保证「认完字就有东西读得下来」 |
| 音频与配图补齐 | 素材须**可开源授权**（自绘 / CC0 / 公版），登记到 `sources.json` 与 `THIRD_PARTY_NOTICES.md` |

> 触发条件：**始终**。只要项目继续维护，内容扩容就是第一优先级。

### 2.2 管理后台补齐 P0 剩余页

现状：`apps/admin` 已有概览 / 邀请码 / 字库 / 古诗 / 短文 / 用户 / 配置页。

| 优化点 | 说明 |
| --- | --- |
| 古诗管理增强（含注音校验） | 逐字注音与原文的等长校验，防止导入出错 |
| 单元与关卡编排 | 目前关卡由生成器按规则生成，可增加可视化编排与覆盖 |
| 内容批量导入 / 导出增强 | 按集合的导入导出已具备；可再加离线编辑回灌与更细的校验报告，降低内容生产门槛 |

### 2.3 质量保障进 CI

| 优化点 | 说明 |
| --- | --- |
| 内容 Schema 校验 | `scripts/content/validate.mjs` 接入 CI，PR 即校验 |
| 类型检查 | `pnpm typecheck`（`vue-tsc`）纳入 CI |
| **掩藏能力「不打包」断言** | 断言构建产物**不含**账号 / 支付 / 小程序 / App 相关代码，把「掩藏」变成可验证的机器检查 |
| 端到端冒烟 | 对 `/content/bootstrap`、登录、答题闭环做接口级冒烟测试 |

## 三、中期优化：体验与规模化

### 3.1 内容下发与缓存

| 优化点 | 说明 |
| --- | --- |
| 内容增量下发 | 当前 `bootstrap` 一次拉全量；内容变大后可改为「先拉 manifest，按 checksum 拉变更文件」 |
| 分页与按需加载 | 字库 / 古诗列表接口支持分页与按单元过滤，减少首屏体积 |
| 素材走 CDN | 音频 / 配图体积明显拖慢加载时，将素材迁到对象存储 + CDN（`ASSET_BASE_URL` 已预留） |
| PWA 缓存策略调优 | 应用外壳预缓存 + 静态资源强缓存 + API 响应不入缓存（已按此设计，可持续校验有效性） |

### 3.2 服务端性能与可靠

| 优化点 | 说明 |
| --- | --- |
| 慢查询与索引复核 | 复习调度（`char_review_states` 的 `{child_id, next_review_at}`）、学情查询（`learning_records`）等热点索引定期复核 |
| 聚合与预计算 | 学情报告由实时聚合改为**按需预聚合**（写入时增量维护统计文档），降低报告接口压力 |
| 单机 → 副本集 | 若数据量或可用性要求上升，MongoDB 从单机升级为副本集（**不做分片，除非确有必要**） |
| 备份与恢复演练 | 定期验证 `scripts/db/backup.sh` / `restore.sh` 可用，避免「有备份但恢复不了」 |
| 健康检查与告警 | `GET /health` 已含 `content_version`，可接入简单探活与告警 |

### 3.3 学习体验

| 优化点 | 说明 |
| --- | --- |
| 复习算法调参 | 在 SM-2 简化变体上，基于真实数据调整间隔与难度系数曲线 |
| 题型自适应 | 同批到期字轮换不同题型；一直答对的字升级为更难题型 |
| 声调跟读反馈 | 本地 F0 提取 + 四声模板比对（不引入按量计费的云端评分，避免破坏开源可运行性） |
| 家长报告可视化 | 趋势、掌握率、薄弱项图表化，支持导出 |
| 无障碍与低端机适配 | 字体下限、触控热区、弱网与低端机降级 |

## 四、长期方向：能力激活与生态

### 4.1 掩藏能力的激活路径

以下能力**代码与契约已就绪、开关默认关闭**，具备外部条件时是「打开开关 + 换一次注入」，而非重写。

| 能力 | 开关名 | 激活前提 |
| --- | --- | --- |
| 手机号 / 微信账号 | `enableAccountAuth` | 企业主体 + 短信 / 微信资质 |
| 账号级云同步 | — | 实名账号体系 |
| 支付与订阅 | `enablePayment` | 商户号 |
| 微信小程序 | `enableMiniprogram` | 企业主体（教育类目需企业资质） |
| iOS / Android App | `enableNativeApp` | 企业开发者账号 |
| 多云评测代理 | `enableCloudAssessment` | 付费语音评测 Key（**无 Key 时整块功能隐藏，绝不显示假分数**） |

> 激活任一能力前，先核对开关的四道防线（路由不注册 / 组件不渲染 / 调用即抛错 / 类型保留）与「不打包」断言。

### 4.2 多学科扩展

`packages/core` 已按**学科无关**设计（判据：*这段逻辑换成英语单词还成立吗？*），识字专属逻辑隔离在 `packages/subject-hanzi`。因此从语文扩到英语 / 数学时，复用发生在**能力层**（SRS、题型框架、身份、仓储、开关），学科层重写。

| 优化点 | 说明 |
| --- | --- |
| 学科走 URL 路径 | `/hanzi` `/english` `/math`，**不开子域**（同源可跨科聚合学情，PWA 只装一次） |
| 新增学科包 | 如 `packages/subject-english`，复用 `core` 与后端内容体系 |
| 成本判断 | 扩科带来的是**内容生产与维护成本**，不是收入（项目免费），须以留存需求为前提 |

### 4.3 内容社区化

| 优化点 | 说明 |
| --- | --- |
| 降门槛贡献流程 | Issue / PR 模板 + 校验脚本 + 评审规则，让「只改 JSON」即可贡献 |
| 众包审核 | 内容质量检查 + 双人校对 + 审计留痕（`audit_logs` / Git 提交） |
| 许可持续扫描 | 进 CI，防止后续引入不兼容许可 |

### 4.4 隐私与合规

| 优化点 | 说明 |
| --- | --- |
| 数据上云告知与删除权 | 明示上传内容与加密方式，提供「注销并删除云端数据」（已实现，持续维护话术与流程） |
| 端到端加密常态化 | 云档案默认关闭、开启时默认加密，服务端零密钥 |
| 部署位置决策 | 起步用境外服务器免备案；国内访问成瓶颈后再评估境内 + 个人 ICP 备案 |
| 第三方许可合规 | 署名 + 许可全文随分发（法定义务） |

## 五、明确暂缓 / 不做

| 项 | 结论 | 原因 |
| --- | --- | --- |
| Redis / 消息队列 / K8s / 微服务 | ⛔ 暂不引入 | 当前负载单机 + 单进程足够；多一个组件多一份故障 |
| 多角色 RBAC 内容后台 | ⛔ 本期不做 | 单人维护下多角色属过度设计，当前只做单管理员（**与企业主体无关**） |
| 音素级云端发音评分（默认） | ⏸️ 可选 | 按量计费会破坏「clone 即跑」；默认关闭、无 Key 整块隐藏 |
| 教材映射数据 | ⛔ 永不提供 | 涉出版社汇编权；改用「课标字表 + 自编单元 / 用户自定义单元」 |
| 数据库分片 | ⏸️ 暂不需要 | 数据规模远未到瓶颈，副本集足够 |
